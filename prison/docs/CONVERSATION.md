## 0. 프로젝트 한눈에 보기 (다른 AI가 이어받을 때 필요한 정보)

**게임**: 「감옥 설계자」 — 프리즌 아키텍트 스타일의 교도소 건설·경영 시뮬레이션. 브라우저(휴대폰 우선)에서 실행되는 HTML5 게임. 서버·회원가입·결제·광고 없음.

**기술 스택**: TypeScript + Vite 7 + Canvas 2D, Vitest 5(테스트), Playwright(playwright-core, 헤드리스 Chromium)로 휴대폰 뷰포트 e2e. Node.js 22.

**실행**
```bash
cd prison
npm install
npm run dev      # 개발 서버 (같은 Wi-Fi 휴대폰에서 http://<PC IP>:5173)
npm run build    # 타입검사 + 빌드 + play/index.html(단일 파일) 생성
npm test         # Vitest 31개 (규칙·기능·시뮬레이션·봇 밸런스)
npm run e2e      # 헤드리스 Chromium 휴대폰 뷰포트 3종 실기동 테스트
```
`prison/play/index.html` 한 파일만 휴대폰 브라우저로 열면 바로 실행됩니다.

**폴더 구조**

**핵심 규칙**
- 44×44 격자, 왼쪽 2열 도로(출입구). 벽·울타리는 모두 막고, 일반 문은 누구나(탈주자 포함) 통과, 감옥문은 직원과 질서 있는 이동만 통과.
- 보안 분석: 지도 테두리에서 벽·울타리·감옥문을 제외한 칸으로 flood fill → 닿는 칸은 "취약". 방은 같은 구역의 연결 칸 집합이며 크기·필수 물건·밀폐(취약 칸 없음) 조건을 모두 채워야 유효.
- 수감자 욕구 7종(배고픔·피로·위생·운동·여가·자유·불안) → 기분 → 분노(등급·성향 배수). 분노가 높으면 싸움/탈주, 분노한 수감자 25% 이상이면 폭동.
- 게임 시간 1시간 = 실제 8초(1×), 하루 3.2분. 속도 1×/2×/4×, 아침까지 빨리 감기 12×.
- 경제: 자정 정산(수감자 등급별 보조금 − 급여), 식재료, 노동 수입, 벌금(탈주 $1,500·사망 $2,500), 평판 0이면 해임, 자금 −$8,000이면 파산.
- 목표 7장(기초 공사 → 첫 수감자 → 감방동 → 질서 → 복지와 노동 → 대형 교도소 → 명예 교도소장).

**상태**: 베타 2. 자동 테스트 31개 통과, 휴대폰 뷰포트 3종 e2e 오류 0. 실기기(iOS Safari/Android Chrome)와 사람 플레이 테스트는 미수행.

## 4. 다른 AI에게 이어서 부탁할 때 참고할 사항

- 밸런스 수치는 `prison/src/data/*.ts`(경제·정책·사건·프리셋)와 `prison/src/sim/prisoner.ts`(욕구 상승/회복률, 사고 확률), `prison/docs/DESIGN.md`에 정리되어 있음.
- 시뮬레이션은 DOM 없이 순수 TS라 `tests/`의 방식대로 헤드리스로 돌려 볼 수 있음(`newGame(seed, 'quick'|'empty', 난이도)` → `run(state, 초)` → 상태 확인). 같은 시드·같은 입력이면 결과가 같음(결정적).
- 새 기능을 넣을 때 순서: 데이터 정의 → sim 로직 → `engine.ts`의 Action 추가 → UI(toolbar/panels/app) → 테스트 → `npm run build` → `npm run e2e`.
- 알려진 제한: 실기기 미검증, 갇힌 수감자는 구출되지 않음(직원만 구출), 지도 확장·터널 외 밀수품·면회·교육 시스템 없음, 시트를 열면 시뮬레이션이 멈춤(설계 선택).
- 다음 작업 제안: 실기기 터치/오디오/FPS 확인 → 사람 플레이 3~5판으로 5~7장 난이도와 사건 체감 조정 → 지도 확장 구매, 교도관 순찰 구역, 면회·교육 프로그램, PWA.
