# 데이헝거 (Day Hunger) — 벽 짓고 살아남기, 모바일 협동 생존

스타크래프트 유즈맵 "벽짓살(벽 짓고 살아남기)" 장르를 모바일 브라우저용으로 다시 만든 게임입니다.
낮에는 자원을 캐서 벽·포탑을 짓고, 밤에는 가장자리에서 몰려오는 좀비를 막습니다. 배고픔도 관리해야 합니다.
**혼자서도, 친구와 최대 4명이 같은 세계에서 협동으로도** 할 수 있습니다.

> 한 문장: **낮 90초 동안 얼마나 잘 준비했느냐가 밤 60초를 결정하는 생존 디펜스.**

## 바로 실행하기

Node.js 22 이상이 필요합니다.

```bash
cd dayhunger
npm install
npm start          # 데이헝거 서버 실행 중: http://localhost:8080
```

- **혼자 하기**: 브라우저에서 위 주소를 열고 "혼자 하기". 서버 없이 브라우저 안에서만 시뮬레이션이 돕니다.
- **같은 Wi-Fi의 휴대폰**: 터미널에 표시되는 `http://<PC의 IP>:8080` 주소를 휴대폰 브라우저(Chrome/Safari)로 여세요.
- **협동**: 한 명이 "방 만들기" → 4자리 코드를 친구에게 알려줌 → 친구는 같은 주소에서 "참가". 방장이 "시작". 게임 중에도 참가할 수 있습니다.
- 홈 화면에 추가하면(사파리 공유 → 홈 화면에 추가) 전체 화면 앱처럼 실행됩니다.

## 게임 규칙

| 구분 | 내용 |
| --- | --- |
| 낮 (90초) | 나무🪵·바위🪨·열매🍎를 채집하고 건설. 새벽마다 보급(나무 4+일수, 돌 2+일수, 식량 2) |
| 밤 (60초) | 적이 맵 가장자리에서 출현. 벽을 돌아갈지 부술지 스스로 판단(체력이 낮은 벽을 노림) |
| 배고픔 | 2초마다 1씩 감소(밤엔 1.5배). 0이 되면 체력이 닳음. 배고픔 60 이상이면 서서히 회복 |
| 승리 | 10일째 아침을 맞이하면 승리. 이후 "무한 모드"로 계속 가능 |
| 패배 | 모든 플레이어가 동시에 쓰러지면 게임 오버. 협동에서는 동료가 살아 있으면 아침에 부활 |
| 괴수 | 5일·9일 밤에는 보스(체력 900)가 옵니다 |

### 적

| 이름 | 체력 | 속도 | 공격 | 등장 |
| --- | --- | --- | --- | --- |
| 좀비 | 40 | 느림 | 8 | 1일~ |
| 러너 | 22 | 빠름 | 5 | 3일~ |
| 브루트 | 160 | 매우 느림 | 24 | 5일~ |
| 괴수(보스) | 900 | 매우 느림 | 40 | 5일·9일 밤 |

적 체력은 날마다 12%씩 늘고, 마릿수는 날짜와 인원수에 따라 늘어납니다. 낮이 되면 남은 적은 15초 안에 타서 사라집니다.

### 건물

| 건물 | 비용 | 체력 | 설명 |
| --- | --- | --- | --- |
| 나무 벽 | 🪵2 | 50 | 값싼 벽 |
| 돌 벽 | 🪨3 | 140 | 튼튼한 벽 |
| 문 | 🪵3 | 40 | 우리만 지나감 |
| 포탑 | 🪵5 🪨4 | 80 | 5칸 안의 적을 0.6초마다 10 피해 |
| 모닥불 | 🪵4 🪨2 | 40 | 근처 아군 회복(초당 1.5), 근처에서 먹으면 배고픔 +45(평소 +30) |
| 밭 | 🪵4 🍎1 | 30 | 40초마다 식량 3 수확 |

수리: 🪵1로 체력 +25. 철거: 재료 절반 환불. 건설 범위는 내 주변 3칸(7×7). 맵 가장자리 한 줄에는 지을 수 없습니다.

## 조작

| 동작 | 휴대폰 | PC(테스트용) |
| --- | --- | --- |
| 이동 | 왼쪽 아래 조이스틱 | WASD / 방향키 |
| 채집·공격 | 오른쪽 큰 ⛏️ 버튼(꾹 누르면 연속) | 스페이스 |
| 건설 | 🧱 → 목록에서 선택 → 지을 곳 탭. 🧱 다시 누르면 취소 | B, 숫자 1~8로 바로 선택, Esc 취소 |
| 먹기 | 🍎 버튼 | E |
| 빠른 채팅 | 💬 (타이핑 없이 6가지 문구) | C |

채집·공격 버튼은 근처에 적이 있으면 공격, 없으면 바라보는 방향의 나무/바위/덤불/익은 밭을 캡니다.

## 협동을 인터넷으로 하려면

같은 Wi-Fi가 아니라면 서버를 인터넷에 올려야 합니다. 서버는 `PORT` 환경변수를 읽는 평범한 Node 앱이라 Railway, Render, Fly.io, 개인 VPS 어디든 올릴 수 있습니다.

```bash
# 예: VPS에서
cd dayhunger && npm install --omit=dev && PORT=80 npm start
```

HTTPS 뒤(리버스 프록시)에 두면 클라이언트가 자동으로 `wss://`로 접속합니다. WebSocket 경로는 `/ws`, 상태 확인은 `/health`.

## 앱으로 설치하기

### 안드로이드 APK (자동 빌드)

GitHub Actions가 `dayhunger/` 아래가 바뀔 때마다 APK를 만들어 릴리스에 올립니다.

1. 저장소의 **Releases → "데이헝거 안드로이드 (최신 빌드)"**(태그 `dayhunger-latest`)에서 `dayhunger.apk`를 휴대폰으로 내려받습니다.
   직접 링크: `https://github.com/bamtolking/MyGame/releases/download/dayhunger-latest/dayhunger.apk`
2. 설치할 때 "출처를 알 수 없는 앱" 허용을 켭니다(디버그 서명이라 스토어 밖 설치용입니다).
3. 앱을 열면 "혼자 하기"는 서버 없이 바로 됩니다. 협동은 메뉴의 **협동 서버 주소**에 서버를 적으면 됩니다
   (같은 Wi-Fi면 `192.168.0.10:8080` 같은 PC 주소, 인터넷이면 배포한 `https://…` 주소).
   앱을 배포하기 전에 `client/js/config.js`의 `DEFAULT_SERVER`에 서버 주소를 적어 두면 사용자가 입력하지 않아도 됩니다.

수동으로 빌드하려면(Android Studio 또는 JDK 21 + Android SDK 필요):

```bash
npm install
npm run android:apk        # www/ 생성 → Capacitor 동기화 → android/app/build/outputs/apk/debug/app-debug.apk
npm run android:open       # Android Studio에서 열기 (스토어용 release 서명은 여기서 Build → Generate Signed Bundle)
```

- 앱 이름·패키지: `capacitor.config.json` (`com.bamtolking.dayhunger`). 아이콘: `npm run icons` (SVG를 PNG로 다시 그림).
- 안드로이드 뒤로가기: 패널 닫기 → 건설 취소 → 두 번 누르면 메뉴로 → 메뉴에서 누르면 종료.

### 아이폰 / 홈 화면 앱 (PWA)

서버 주소를 Safari로 연 뒤 **공유 → 홈 화면에 추가**하면 전체 화면 앱처럼 실행되고, 한 번 연 뒤에는 오프라인에서도 "혼자 하기"가 됩니다(서비스 워커 캐시).
스토어용 iOS 앱은 macOS의 Xcode가 필요합니다: `npx cap add ios && npx cap open ios`.

## 구조

```
shared/constants.js   수치·정의(타일, 건물, 적, 낮밤 길이, 웨이브) — 밸런스는 여기만
shared/game.js        시뮬레이션(순수 JS, DOM 없음): 월드 생성, 이동/충돌, 채집, 건설, 낮밤, 적 AI(다익스트라 흐름장), 포탑, 직렬화
server/index.js       정적 파일 + WebSocket 방 관리. 방마다 Game 하나를 20틱/초로 돌리고 10회/초 상태 전송
client/js/main.js     화면 전환, 솔로(LocalSession)/협동(NetSession), 메인 루프
client/js/view.js     서버(또는 로컬 Game)에서 받은 full/delta를 적용하는 미러 + 보간 + 효과
client/js/renderer.js Canvas 2D 렌더링(이미지 파일 없음), 밤 조명, 미니맵
client/js/input.js    터치 조이스틱, 버튼, 키보드, 캔버스 탭
client/js/ui.js       HUD, 건설/채팅 패널, 토스트, 결과 화면
tests/                node:test 규칙 테스트
scripts/e2e.mjs       헤드리스 Chromium으로 솔로 + 2인 협동 실기동 검증(스크린샷 e2e-out/)
```

- 솔로와 협동이 **같은 시뮬레이션 코드**를 씁니다. 솔로는 브라우저가 `Game`을 직접 돌리고, 협동은 서버가 돌립니다.
- 적 경로: 살아있는 플레이어를 출발점으로 다익스트라를 돌려 흐름장을 만듭니다. 건물 타일은 `1 + 체력/12` 비용으로 지나갈 수 있어, 멀리 돌아가는 것보다 싸면 벽을 부수고 들어옵니다(벽짓살의 핵심 재미).
- 네트워크: 서버가 권위를 가지며 클라이언트는 입력(조이스틱 벡터, 버튼)만 보냅니다. 상태는 10Hz로 오고 클라이언트가 보간합니다.

## 명령

```bash
npm test        # 규칙 테스트 (1초)
npm run e2e     # 헤드리스 Chromium 실기동 검증 (약 20초, 스크린샷 e2e-out/)
npm run dev     # 파일 바뀌면 서버 자동 재시작
```
