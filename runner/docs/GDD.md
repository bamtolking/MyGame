## 1. 제목 · 한 줄 소개 · 세계관

### 1.1 제목
**야식 대질주** — 부제 「보름달까지 달려라!」

### 1.2 한 줄 소개
도깨비 방망이로 깨어난 야시장 간식들이 몸이 식기 전에 보름달 잔치까지 달려가는 두 버튼 자동 달리기 게임이다. 에너지, 뽑기, 강화, 광고, 결제가 없고 실력만큼 멀리 간다.

### 1.3 세계관 (오리지널 IP, 「대박수비대」와 같은 '도깨비 야시장' 세계)
- **발단**: 한가위 보름밤 자정, 장난꾸러기 도깨비 '뚝딱이'가 좌판을 방망이로 "뚝딱!" 두드린다. 호떡, 붕어빵, 떡꼬치, 어묵, 달고나, 군고구마가 눈을 뜬다.
- **규칙**: 마법은 몸이 **따끈한 동안에만** 이어진다. 식어 버리면 다시 평범한 간식이 된다. 달리는 동안 조금씩 식고, 부딪히면 확 식고, 꿀물을 마시면 다시 데워진다.
- **목표**: 언덕 위 '보름달 잔치'에 닿은 간식은 한 해 동안 사람들에게 가장 사랑받는다는 전설이 있다. 길에는 달에서 흘러내린 **별사탕**이 깔려 있고, 이것이 곧 길잡이다.
- **여정**: 야시장 골목 → 포장마차 강변 → 불꽃놀이 다리 → 보름달 언덕(엔딩). 무한 달리기에서는 네 번째 풍경인 '새벽 지붕길'까지 순환한다.
- **도깨비 뚝딱이**: 적이 아니다. 타이틀 화면, 결승 깃발, 엔딩에만 나오는 응원꾼이다.

### 1.4 IP 원칙과 명칭 매핑
금지 목록은 다음과 같다: 쿠키, 오븐, 진저브레드 실루엣, 곰 모양 젤리, "BONUSTIME", Devsisters의 모든 명칭과 로고. 가져오는 것은 메커니즘뿐이다.

| 영구 점수 배수 | 서브웨이 (×30) | 흐름은 한 판 안에서만 쌓이고 +50%가 상한이다. |
| 가로 고정, 회전 강요 | 쿠키런, 여러 HTML5 게임 | 세로 게임보이 배치와 '눕혀서 하기'. "돌려 주세요" 차단 화면은 없다. |
| 화면비에 따라 점수가 달라짐 | 오븐브레이크 (젤리 효과 범위) | 시뮬은 뷰포트를 읽지 않는다. 모든 범위는 월드 단위다. |
| 렉 뒤에 입력이 몰려서 실행됨 | 오븐브레이크 프리즈 버그 | 누적기는 한 번에 최대 5스텝. 250 ms 넘게 멈추면 자동 일시정지. 입력은 타임스탬프로 해당 스텝에 넣는다. |
| 저장 유실 | 버전 올리면 초기화, 사파리 7일 삭제 | 마이그레이션 체인, `_bak` 사본, `persist()`, 백업 코드. |
| 긴 로딩, 접속 필요 | 오븐브레이크 | 단일 파일에 시스템 글꼴만 쓰고 네트워크 요청은 0이다. |
| 색으로만 구분, 이펙트가 장애물을 가림 | 오븐브레이크 후반 | 모양 문법과 이중 외곽선. 위험물은 항상 이펙트 위에 그린다. |
| 반복감, 느린 초반 | 서브웨이, 오븐브레이크 | 6초 워밍업, 600 m마다 풍경 순환, 21 스테이지, 반복 금지 규칙. |

## 3. 조작

### 3.1 입력 두 개

| 입력 | 동작 |
|---|---|
| **점프** 누름 (지상) | 점프. `JUMP_V` 1040, 정점 169 px, 체공 0.65초. |
| **점프** 누름 (공중, 점프가 남아 있음) | 공중 점프. `DJUMP_V` 900, +127 px. |
| **점프** 계속 누름 | 자동 반복하지 않는다. 점프마다 새로 눌러야 한다. 예외: 붕이의 활공, 보름달 잔치의 상승. |
| **슬라이드** 누르고 있기 (지상) | 슬라이드. 판정 상자 52×32. |
| **슬라이드** 누름 (공중) | 빠른 낙하. 중력 ×2.2. 2-3에서 가르치며 티어 0–1에서는 절대 요구하지 않는다. |
| 슬라이드를 누른 채 점프 탭 | 슬라이드에서 뛰어오른다. 착지할 때 슬라이드가 아직 눌려 있으면 다시 슬라이드한다. |
| 보름달 잔치 중 | 점프를 누르고 있으면 올라가고, 떼면 내려간다. |

- 점프 높이는 **고정**이다. 누르는 길이로 높이를 바꾸지 않는다. 이유는 두 가지다. '누르고 있기'는 이미 슬라이드에 쓰이고, 유리 화면에서는 누른 길이를 몸으로 느끼기 어렵다.
- 스와이프, 기울이기, 더블탭 제스처는 **전혀 쓰지 않는다**.

### 3.2 가로 화면 (기본)
- 논리 해상도 960×540을 `scale = min(w/960, h/540)`로 맞춘다. 예를 들어 844×390 화면이면 배율 0.722, 693×390 캔버스가 되고 양옆에 75 px씩 레터박스가 남는다.
- **화면 전체의 왼쪽 절반 = 점프, 오른쪽 절반 = 슬라이드**다. 레터박스 영역도 포함한다. 설정에서 좌우를 바꿀 수 있다.
- 처음 3판 동안 엄지 그림 힌트를 알파 20%로 보여 준다. 레터박스와 안전 영역에만 그리고 바닥 띠(아래 100 논리 px) 위에는 그리지 않는다. 설정 '버튼 표시'로 계속 켜 둘 수 있다.
- 일시정지 버튼은 왼쪽 위 44×44 CSS px이다. 플레이 띠의 오른쪽 25%에는 HUD를 두지 않는다. 다가오는 위험물이 가려지지 않게 하려는 것이다.

### 3.3 세로 화면 — '게임보이' 배치 (정식 모드이고 차단 화면이 아님)
```
┌──────── 390 ────────┐  ← safe-area-inset-top
│  캔버스 390×219       │  같은 960×540 월드, 앞쪽 시야도 같은 740 px (배율 0.406)
├─────────────────────┤
│ HUD 띠 64–72 px      │  따끈함 막대(전폭) / 잔치 글자 · 점수+흐름 불꽃 · 복주머니·최고 기록 막대 / ⏸
├──────────┬──────────┤
│          │          │
│  점프    │ 슬라이드 │  각 패드는 폭 ≥ 180, 높이 ≥ 120 CSS px (390×844에서 약 187×460)
│   ⤒      │    ⤓     │  큰 그림 표시. 좌우 바꾸기 설정을 따른다.
│          │          │
└──────────┴──────────┘  ← safe-area-inset-bottom (홈 인디케이터 위)
```
- 360×640 화면에서는 캔버스 360×203, HUD 64 px, 패드 높이 약 373 px이 된다.
- 세로에서만 렌더에 보조를 준다. 위험물 외곽선을 1.5배로, 별사탕 그림을 1.15배로 그린다. **판정은 바꾸지 않는다.**
- 한 번만 뜨고 닫을 수 있는 안내를 둔다: 「가로로 돌리면 화면이 더 커져요」.
- **'눕혀서 하기'** 설정: 세로 창에서 게임 루트를 CSS로 90° 돌린다(`width:100dvh; height:100dvw`). 포인터 좌표는 (x′,y′) = (y, W−x) 또는 그 거울상으로 다시 매핑한다. 회전 잠금을 켜 둔 iPhone 사용자를 위한 기능이다.
- 시뮬레이션은 뷰포트를 전혀 읽지 않는다. 그래서 별, 기록, 유령, 데일리가 방향과 관계없이 모두 같다.
- 달리는 도중 크기가 바뀌거나 회전하면 자동으로 일시정지한다. '계속'을 누르면 3-2-1 카운트다운(1.5초) 뒤에 이어진다.
- 대비책: 실기 테스트에서 세로의 피격률이 가로보다 25% 이상 높으면, 세로 전용 '편안 속도 85%' 옵션을 추가한다. 이 옵션의 기록은 따로 관리한다.

### 3.4 데스크톱 (키보드와 마우스)

| 키 | 동작 |
|---|---|
| Space, ↑, W, Z | 점프 (누를 때마다 한 번) |
| ↓, S, Shift, X | 슬라이드 (누르고 있기) |
| P, Esc | 일시정지 / 계속 |
| Enter | 결과 화면에서 다시 달리기 |
| (개발 빌드 전용) H | 판정 상자 오버레이 |

- 마우스로 캔버스의 좌우 절반을 클릭해도 터치와 똑같이 동작한다(Pointer Events). 오른쪽 클릭 메뉴는 막는다.

### 3.5 입력 계층 구현 규칙 (`src/ui/input.ts`)
1. 전체 화면 입력 레이어 하나에서 Pointer Events만 받는다. 각 `pointerId`는 처음 누른 구역에 고정한다(`setPointerCapture`). 뗄 때는 `pointerup`, `pointercancel`, `lostpointercapture`를 처리한다.
2. 게임 루트에 거는 CSS와 이벤트 처리:
   - CSS: `touch-action:none; user-select:none; -webkit-user-select:none; -webkit-touch-callout:none;`
   - `html,body`: `overscroll-behavior:none`
   - passive가 아닌 `touchstart` 리스너에서 `preventDefault()`를 호출한다. iOS의 '더블탭 후 누르고 있기' 돋보기가 바로 "2단 점프 뒤 슬라이드" 제스처와 겹치기 때문이다.
   - `contextmenu`, `selectstart`, `gesturestart`도 막는다.
3. DOM HUD는 `pointer-events:none`이다. 예외는 실제 버튼(일시정지)뿐이다.
4. 누름 입력은 `event.timeStamp`와 함께 큐에 넣는다. 각 입력은 시뮬 시간이 그 타임스탬프 이상이 되는 첫 스텝에 전달한다. 한 스텝에는 최대 2개(`MAX_PRESS_QUEUE`)까지 쌓고 스텝마다 1개씩 소비한다. 그래서 두 손가락으로 빠르게 치는 2단 점프가 하나로 합쳐지지 않는다.
5. 슬라이드는 "슬라이드 구역에 눌린 포인터가 하나라도 있으면" 켜진 것으로 본다.
6. 일시정지하거나 창이 가려지면 `InputState.reset()`을 호출한다. 다시 시작할 때 150 ms보다 오래된 누름은 버린다.
7. 패드는 화면 가장자리에서 16–24 px 안쪽에 두고(Safari 뒤로 가기 스와이프 회피), `env(safe-area-inset-*)` 안에 배치한다.

### 3.6 조작 옵션
- **좌우 바꾸기**: 점프가 오른쪽으로 간다.
- **슬라이드 토글**: 한 번 탭하면 0.6초 슬라이드한다. 운동 접근성용이며 P1.
- **버튼 표시**: 엄지 힌트를 계속 켠다.
- **눕혀서 하기**: P1.
- **한 손 모드**: 주로 쓰는 손 쪽 아래 사분면에 두 패드를 위아래로 쌓는다(각 96 px 이상, 빠른 낙하 불가). P2.

### 4.4 판정 상자
- 서 있을 때 36×70이다. 그림이 약 56×84이므로 **폭 64%, 높이 83%**다.
- 슬라이드할 때 52×32다. 왕만두(거대화) 상태에서는 ×2.1이다.
- 획득 판정은 몸 판정 바깥 `PICK_PAD` 16 px까지다. 짝꿍 반짝이가 있으면 +60 px.
- 가시 `^`는 **이중 상자**다. 아래 30×18 위에 끝 12×18을 얹는다. 현재는 30×36 한 상자이므로 교체한다. 삼각형 옆의 빈 공간에 걸리는 억울한 피격을 없애기 위해서다.
- 기둥 `A`는 34×176이다. 한 번 점프한 정점(169 px)보다 높아서 2단 점프가 필요하다.
- 걸림 `v`는 바닥이 9행 −6 px(y = 394)다. 슬라이드 상자와 14 px 여유가 있다.
- 규칙: **위험물 판정은 절대 그림보다 크지 않다.** 그림 실루엣에서 3–6 px 안쪽으로 들인다. 렌더러는 시뮬의 사각형을 그대로 읽어서 그린다.

|---|---:|---:|---:|---:|---:|---|---:|
| 0 | 420 | 10.5 | 1.76 | 273 px | 0.95 | 0–300 m | 0초 |
| 1 | 460 | 11.5 | 1.61 | 299 px | 1.05 | 300–600 m | 28.6초 |
| 2 | 500 | 12.5 | 1.48 | 325 px | 1.18 | 600–900 m | 54.7초 |
| 3 | 545 | 13.6 | 1.36 | 354 px | 1.32 | 900–1200 m | 78.7초 |
| 4 | 590 | 14.75 | 1.25 | 384 px | 1.48 | 1200–1500 m | 100.7초 |

- 반응 예산은 (740 − 40) / v ≥ 0.8초다. 그래서 **다칠 수 있는 속도의 절대 상한은 약 875 px/s**이고, 실제 운영 상한은 640 px/s다.
- 불꽃 질주(×1.7 = 1088 px/s)는 상한을 넘지만 무적이고 장애물을 부수므로 괜찮다.
- 속도는 **청크 경계에서만** 바뀐다. 현재 `SPEED_EASE` 60은 게임 로직에서 삭제한다. 청크 안에서 속도가 바뀌면 검증한 내용과 달라지기 때문이다.

### 4.6 무적과 히트스톱

| 상황 | 무적(초) |
|---|---:|
| 장애물 피격 `HIT_IFRAMES` | 1.2 |
| 구덩이 `FALL_IFRAMES` | 1.6 |
| 파워업 종료 유예 `POWER_AFTER_IFRAMES` | 1.0 |
| 보름달 잔치 복귀 `BONUS_RETURN_IFRAMES` | 1.5 |
| 이어달리기, 되살아나기 | 2.0 |

- 무적 중에 닿았던 위험물은 '무해' 표시가 붙고 이후에도 절대 때리지 않는다.
- 무적은 **어떤 위험물과도 겹치지 않을 때에만** 끝난다. 겹쳐 있으면 한 스텝씩 연장한다.
- 깜빡임은 10 Hz이고 렌더에서만 처리한다.
- 히트스톱은 시뮬 안의 정지 카운터다. 피격 때 `HITSTOP_STEPS` = 4스텝(67 ms), 부수기 때 2스텝, 획득 때는 0이다. 정지 중에는 버퍼, 코요테, 무적 타이머가 흐르지 않고 입력은 큐에 쌓인다.

### 4.7 프레임 루프 (`src/main.ts`)
- rAF 누적기에 `min(frameDt, 0.25)`를 더한다. 한 프레임에 최대 `MAX_CATCHUP_STEPS` = 5스텝까지 돌리고, 남는 시간은 버린다. 렉 뒤에 순간이동하는 일이 없다.
- 렌더는 이전 상태와 현재 상태를 `alpha = acc/DT`로 보간한다. 대상은 카메라 x와 플레이어 x·y다.
- 렌더는 60 Hz로 제한한다. 120 Hz 화면에서는 rAF를 하나씩 건너뛴다. '배터리 절약'을 켜면 30 fps로 그리고 DPR을 1.5로 제한한다. 평소 DPR 상한은 2다.
- 자동 일시정지 조건: 한 프레임 간격이 250 ms를 넘을 때(`STALL_PAUSE_MS`), `visibilitychange`(hidden), `pagehide`, `blur`, `resize`, `orientationchange`.
- 일시정지 중이거나 메뉴에서는 rAF를 멈추고 변경이 있을 때만 다시 그린다. `AudioContext`도 일시정지한다.

### 4.8 카메라 (렌더 전용)
- 수평 기준점은 x = 220 고정, 줌은 1 고정이다.
- 수직으로는 스프라이트 윗부분이 화면 위 40 px 안쪽으로 들어갈 때만 위로 따라간다. 임계감쇠 스프링(ω = 9 rad/s)으로 최대 160 px까지 움직이고, 기준선 아래로는 내려가지 않는다. 발판에서 2단 점프를 해도 화면 밖으로 나가지 않게 하려는 것이다.
- 불꽃 질주 중에는 기준점을 0.3초에 걸쳐 x = 160으로 옮길 수 있다(선택 사항, P2).

### 4.9 렌더 전용 연출 수치
- **찌그러짐과 늘어남**
  - 도약: sx 0.85, sy 1.18을 주고 120 ms에 걸쳐 1로 돌아온다.
  - 공중 점프: sx 0.9, sy 1.12에 250 ms 동안 360° 회전한다.
  - 착지: sy = 1 − 0.2·min(1, vy/1800), sx = 1/sy이고 100 ms에 걸쳐 회복한다.
  - 기준점은 발이다. sx·sy ≈ 1을 유지한다.
- **슬라이드**: 60 ms 동안 낮은 자세로 전환하고, 50 ms마다 먼지를 낸다.
- **화면 흔들림**: trauma² × 최대 10 px이고 평행이동만 한다(회전 없음). 피격 +0.6, 구덩이 +0.8, 부수기 +0.25이고 초당 1.5씩 줄어든다. 흔들림과 파티클은 `fxRng` 또는 `Math.random`을 쓰고 **시뮬 RNG는 절대 쓰지 않는다.**
- **속도선**: 티어 4 이상이거나 질주 중일 때만 그린다.

## 5. 런 구조

### 5.1 따끈함 (체력이자 시계)
- 최대값 `BASE_MAX_HP`는 100이다. 캐릭터에 따라 85 또는 90일 수 있다.
- 식는 속도는 `DRAIN_BY_TIER` = [0.95, 1.05, 1.18, 1.32, 1.48, 1.66] 따끈함/초이고 캐릭터 `drainMul`을 곱한다. 보름달 잔치 중에는 식지 않는다.
- 후반 가속(`LATE_DRAIN_START` 300초, `LATE_DRAIN_PER_S` 0.025): 300초 이후에는 초당 0.025×(t−300)이 더해진다. 완벽하게 플레이해도 약 390초 안팎에 끝난다.
- 강제 종료는 `RUN_CAP_T` = 600초다.
- 위기 상태는 20% 미만(`LOW_HP_FRAC`)이다.
  - 화면 가장자리에 서리가 낀다. 알파 0.35 이하이고 붉은 점멸은 쓰지 않는다.
  - 1 Hz 이하로 '덜덜' 소리가 나고 막대가 느리게 맥박친다.
  - 처음 50% 아래로 떨어지면 2초짜리 토스트를 한 번 띄운다: 「계속 식어요 — 꿀물로 데워요」.
- 따끈함이 0이 되면 쓰러진다. 5.7절의 두 번째 기회 순서를 적용한다.

### 5.2 꿀물
- **꿀물**은 +14다. 청크의 `P` 슬롯에 170 m(`POTION_GAP_M`)마다 채운다. 4번째마다 **꿀단지** +32(`BIG_POTION_EVERY` 4)가 나온다.
- 평균은 170 m당 18.5다. 무피격 기준으로 티어 0에서는 약간 흑자, 티어 5에서는 대략 손익분기다.
- 스테이지의 `P` 슬롯은 제작자가 직접 배치한다. 달리는 시간 15초마다 1개 이상 둔다.
- 짝꿍 깍순이의 **꿀물 한 방울**은 +8이다.

### 5.3 위험물과 피해

| 위험물 | 글리프 | 요구 동작 | 피해 | 시각 문법 |
|---|---|---|---:|---|
| 가시 | `^` | 점프 | −15 | 땅에서 솟은 날카로운 ▲ |
| 높은 탑 | `A` | 2단 점프 | −15 | 몸보다 큰 기둥, ⇈ 셰브론 |
| 걸림 | `v` (9행) | 슬라이드 | −15 | 위에서 매달린 블록, ▼ 줄무늬 |
| 낮은 천장 | `v` (8행) | 선 채로 통과, 점프 금지 | −15 | 같은 블록, 더 높이 |
| 구덩이 | 지면 `.` | 점프 | −20 + 구출 | 땅이 끊김, 위에 별사탕 아치 |

- **구덩이 구출**: `RESCUE_BOUNCE_V` 1250 px/s로 튕겨 올리고, 1.4초 동안 다리(`RESCUE_BRIDGE_T`)를 놓고, 1.6초 무적을 준다. 즉사는 **절대 없다.** 구덩이는 티어 1부터 나오며 스테이지에서는 1-5부터다.
- 피격하면 넉백은 없고 4스텝 히트스톱과 1.2초 무적이 걸리며 흐름이 0이 된다. 결과 화면을 위해 `lastHit`와 `hitsBy`에 기록한다.
- 움직이는 위험물(날아오는 것, 떨어지는 것)은 v1에 **없다**. 도입하려면 시간을 아는 검증기와 1.0초 이상의 예고, 전용 경고음이 먼저 있어야 한다(v2).

### 5.4 획득물, 점수, 흐름
점수 값은 고정이고 절대 업그레이드되지 않는다.

| 획득물 | 글리프 / 출처 | 점수 | 흐름 배수 적용 |
|---|---|---:|:-:|
| 별사탕 | `o` | 10 | ✓ |
| 왕별사탕 | `O`, 빈 `?` 슬롯 | 60 | ✓ |
| 하늘 별사탕 | 보름달 잔치 | 20 | ✓ |
| 한 줄 완성 | 별사탕이 12개 이상인 청크에서 100% 획득 | 100 | ✓ |
| 엽전 | `c` | 5 + 엽전 1 | ✗ |
| 잔치 글자 | `L` 슬롯 | 50 | ✗ |
| 보름달 떡 | 잔치 끝, 1개 | 500 | ✗ |
| 황금 복주머니 | `B` (스테이지 전용) | 200 | ✗ |
| 부수기 | 왕만두·질주로 장애물 파괴 | 30 | ✗ |
| 아슬아슬 | 판정 상자와 14 px 이내로 스쳐 지나감 | 25 | ✗ |
| 거리 | 1 m당 | 1 | ✗ |

**흐름** (`streak`)
- 위험물 하나를 무피격으로 지나면 +1, 아슬아슬이면 +2다.
- 10마다 흐름 배수 적용 항목의 점수가 +10%(`STREAK_STEP`, `STREAK_BONUS`)이고, 최대 +50%(`STREAK_MAX`)다.
- 피격하거나 구덩이에 빠지면(방울막이 막아 준 피격 포함) 0이 된다.
- 점수 옆에 불꽃 고리로 표시하며 단계마다 불꽃이 커진다.
- **게임 전체에서 배수는 이것 하나뿐이다.** 배수 위에 배수를 겹치지 않는다.

**점수 기대값**: 현재 봇 스윕 기준 초보 약 2만, 중간 3–5만, 숙련 10만 안팎이다. 999,999를 넘지 않음을 테스트로 보장한다. 모든 기록에는 `SCORE_VERSION`을 찍는다. 밸런스를 바꾸면 버전을 올리고 기록판을 새로 연다. 옛 기록은 버전별로 보관하며 몰래 평가절하하지 않는다.

**음향**: 400 ms 안에 연달아 먹으면 장조 오음음계로 한 음씩 올라가고, 최대 10단계에서 유지한다. 효과음 사이는 최소 45 ms, 동시 발음은 최대 6개다. 한 줄 완성은 화음, 왕별사탕은 3화음이다.

### 5.5 보름달 잔치 (BONUSTIME)
- **글자 배치**
  - `L` 슬롯은 70 m(`LETTER_GAP_M`)마다 채운다. 항상 **아직 못 모은 가장 앞 글자**를 놓는다. 놓친 글자는 다음 슬롯에 다시 나온다.
  - 가장 빠르면 350 m, 약 33초에 첫 잔치가 열린다. 이후 대략 45–60초 간격이다.
  - 글자는 각자 색이 다른 종이 등불 모양이다.
- **진행**
  - 떠오르기 0.7초(`BONUS_LIFT_T`) 뒤 **10초**(`BONUS_T`) 동안 하늘을 난다. 시간은 **시뮬 초**로 잰다.
  - 조작: 점프를 누르고 있으면 올라간다(`FLY_THRUST` 5200). 떼면 내려간다(`FLY_GRAVITY` 2400). 최대 속도는 700 px/s다.
  - 하늘 별사탕, 왕별사탕, 엽전 줄이 이어진다. 식지 않고, 위험물도 피해도 없다.
  - 끝에는 **보름달 떡**(500점) 1개가 가운데 줄에 있다.
- **왕보름달 잔치**: 다섯 번째 글자를 먹는 순간 따끈함이 20% 미만이면 15초(×1.5)로 늘어나고 종료할 때 최대치의 15%를 회복한다.
- **종료**: `landing` 청크로 착지하고 1.5초 무적을 준다. 스트림은 재시작하고, 메인 청크 순번은 그대로 이어진다(7.5절).
- 잔치 중에는 왕만두, 질주, 자석, 캐릭터 스킬 타이머가 **멈춘다**. 끝나면 이어서 흐른다. "어떤 보상도 다른 보상을 줄이거나 없애지 않는다"는 규칙을 쌍별 단위 테스트로 강제한다.

### 5.6 파워업 (`?` 슬롯, 120 m마다)

| 이름 | 코드 | 지속 | 효과 |
|---|---|---:|---|
| 왕만두 | `giant` | 4.5초 | 크기 ×2.1, 무적, 장애물을 부술 때마다 +30 |
| 불꽃 질주 | `dash` | 3.2초 | 속도 ×1.7(티어 5에서 1088 px/s), 무적, 부수기 |
| 엿가락 자석 | `magnet` | 7초 | 반경 190 px, 끌어당김 1100 px/s |

- 종류는 `levelRng`로 고른다. 가중치는 35/30/35이고 **같은 종류가 연속으로 나오지 않는다.** 현재는 균등 무작위이므로 바꾼다.
- 이미 켜진 파워업을 또 먹으면 시간이 처음부터 다시 흐른다. 남은 시간에 더하지 않는다.
- 모든 파워업은 끝날 때 1.0초 유예 무적을 준다.
- 질주가 끝나면 1500 px/s² 이상의 감속으로 티어 속도에 복귀한다(약 0.3초 이내). 유예 무적 동안 이 복귀가 끝나므로, 빠른 속도 그대로 다음 장애물에 부딪히는 일이 없다.

### 5.7 두 번째 기회 규칙 (돈으로 사는 부활은 없다)
따끈함이 0이 되면 아래 순서로 처리한다.
1. **캐릭터 특성으로 되살아나기**(고구미): 달리던 캐릭터가 판당 한 번, 최대치의 35%로 되살아나고 2초 무적을 받는다.
2. **이어달리기**(무한 달리기 전용, 1-6 클리어로 해금): 1.0초 교대 연출이 나온다(시뮬 정지 60스텝). 파트너가 **자기 최대치의 50%**로 한 번 이어받고 2.0초 무적을 받는다. 점수, 흐름, 글자, 짝꿍은 그대로 이어진다. 켜져 있던 파워업은 1.0초 유예 무적과 함께 끝난다.
3. **쓰러짐**: 0.8초 동안 쓰러지는 연출(`DYING_T`) 뒤 결과 화면으로 간다.

- "이어하기?" 창은 어디에도 없다.
- 그 밖의 두 번째 기회는 구덩이 구출 튕김, 어묵이의 방울막, 해돌이의 구덩이 면제뿐이다.

### 5.8 난이도 곡선 (무한 달리기와 오늘의 골목)
- **시작**: 첫 판에만 1.5초 카운트다운이 있다. 다시 달리기에서는 생략한다. 이어서 `landing`(16열)과 `warmup`(48열, 신규 특수 청크)이 나와 **처음 약 6초는 위험물이 없다**.
- **티어 상승**: 300 m(`TIER_EVERY_M`)마다 한 티어씩 올라 1,500 m에서 640 px/s가 된다.
  - 티어가 오르기 1초 전에 소리가 차오르고 속도선이 나온다. 시뮬이 `speedUpSoon` 이벤트를 낸다.
  - 오른 직후 첫 청크는 적응용이다. `tiers[0] ≤ tier−1`이고 위험물이 3개 이하인 청크 중에서 고른다.
- **상한 이후**: 속도는 더 오르지 않는다. 티어 5 청크 조합, 밀도, 후반 가속으로만 어려워진다.
- **감독 규칙**: 위험물이 있는 청크가 4개 연속이거나 긴장 구간이 25초를 넘으면 쉼 청크(`rest` 태그)를 강제로 넣는다. 45–60초마다 볼거리 청크(`setpiece`, 풍경당 1개)를 넣는다.

### 5.9 풍경 순환
- 600 m(`BIOME_EVERY_M`)마다 바뀐다: 야시장 골목(`market`) → 포장마차 강변(`riverside`) → 불꽃놀이 다리(`bridge`) → 새벽 지붕길(`dawn`) → 다시 처음.
- 풍경마다 팔레트, 시차 레이어 4장, 음악 키·BPM, 위험물 스킨이 다르다. **실루엣과 판정은 모든 풍경에서 같다.** 바뀔 때 1초 교차 페이드한다.

## 7. 레벨 생성

### 7.1 청크 형식 (`src/sim/chunk.ts`, 현재 형식 유지)
- 12행 ASCII이고 마지막 줄이 지면(11행)이다. 폭은 12–48열이며 평균 약 20열이다.
- 필드: `{ id, tiers:[a,b], tags, weight?, biomes?, signs?, rows }`.
- 글리프 목록:
  - `=` 지면. 11행의 `.`은 구덩이.
  - `-` 한 방향 발판.
  - `^` 가시, `A` 높은 탑, `v` 걸림.
  - `o` 별사탕, `O` 왕별사탕, `c` 엽전.
  - `P` 꿀물 슬롯, `?` 파워업 슬롯, `L` 글자 슬롯.
  - **`B` 황금 복주머니 (신규)**: 스테이지에서만 복주머니가 되고, 그 밖의 모드에서는 엽전으로 바뀐다.
- `tags`의 1차 계열은 `jump`, `double`, `slide`, `pit`, `platform`, `combo`, `rhythm`, `choice`, `tunnel`, `stairs` 중 하나 이상이다. 특수 태그는 `rest`, `sky`, `special`, `tutorial`, `setpiece`, `warmup`.
- 변형 칸(선택, P2): 칸 하나를 "50% 가시 / 50% 별사탕"처럼 두 값 중 하나로 정한다. 청크당 k ≤ 3개로 제한하고 2^k개 조합을 **모두** 검증한다.

### 7.2 티어와 라이브러리 목표
- 청크는 속도 티어 `[a,b]` 범위에 속한다. 범위 안의 모든 속도에서 증명한다(`VALIDATE_SPEED_STEP` 20 px/s마다).
- 현재 게임플레이 청크는 77개이고 티어별 출전 가능 수는 25 / 37 / 53 / 59 / 58 / 44다.
- 목표: 게임플레이 청크 **110개 이상**, 쉼·하늘 청크를 뺀 티어별 출전 가능 수 **28개 이상**. 특히 티어 0–1을 보강한다.
- 특수 청크: `landing`, `warmup`(신규), `finish_runout`, 튜토리얼 6개, 하늘 6개, 쉼 4개 이상, 볼거리 4개(풍경당 1개).

### 7.3 공정성 검증기 — CI 관문 (전부 통과해야 병합)

| 관문 | 내용 |
|---|---|
| G1 구조 | 12열 이상. 양 끝 지면 3칸 이상. 앞 4열과 뒤 3열에는 위험물 금지(`lintChunk`, 현재 있음). 그래서 청크 이음매에는 항상 빈 타일이 7칸 이상 있다. |
| G2 존재 증명 | 범위 안 20 px/s마다, 판정 +5 px(`VALIDATE_PAD`)로 무피격 경로가 존재해야 한다(`solve`, 현재 있음). |
| G3 위상 견고 | 결정 격자 S프레임의 **모든 위상**이 통과해야 한다. S는 `VALIDATE_PHASE_FRAMES` = [15,15,12,12,9,9]. 그러면 강제되는 모든 동작에 250 / 200 / 150 ms 이상의 여유 창이 생긴다. |
| G4 능력 제한 | 기본 능력만으로 검증한다(`maxJumps` 2, 활공 없음). 티어 0–1은 `fastFall:false`. |

| G6 간격 | 같은 동작을 요구하는 위험물은 1열 이하로 붙거나(한 덩어리로 취급) `ceil(jumpLen(v_max)/40)+1`열 이상 떨어져야 한다. 슬라이드↔점프 전환은 티어 4 미만에서 빈 열 4개 이상. 예외는 `rhythm` 태그와 티어 4 이상. |
| G7 빈 구간 | 티어 최저 속도로 1.5초(≈630 px) 넘게 획득물도 위험물도 없는 구간 금지. |
| G8 사람 모형 봇 | 청크 단위로 최저·최고 속도 × 노이즈 시드 200. 통과율 하한은 티어 0부터 95 / 92 / 89 / 86 / 83 / 80%. 측정값으로 티어를 자동 제안한다. |
| G9 이음매 흡수 | 시드 300 × 300초. 이음매 문제를 잡기 위해, 청크 앞 4열에서 난 피격 비율이 균등 기대치의 1.5배를 넘으면 실패. |

- 검증 결과는 `hash(청크 rows, tiers, PHYSICS_HASH)`를 키로 캐시한다. 커밋마다 바뀐 청크만 검증하고, G8과 G9 전체는 야간에 돈다.
- **사람 모형 봇** (`tests/bot.ts` 확장, `humanBot`)
  - 740 px 시야 안에서 250 ms 이상 보인 위험물만 계획에 넣는다.
  - 도약 가능 구간의 한가운데를 노린다.
  - 타이밍 노이즈는 균등분포 3개의 합(σ ≈ 50 ms)이다. 정확한 사칙연산만 쓰고 `Math.log`는 쓰지 않는다.
  - 입력을 놓치는 확률은 2%다.
  - 등급: 초보 σ 80 ms / 지연 300 ms / 놓침 5%, 캐주얼 60/250/3%, 숙련 45/220/1%, 달인 20/180/0%.

### 7.4 이어 붙이기 규칙
- `NO_REPEAT` 8에 더해 같은 id는 60초 안에 다시 나오지 않는다(`CHUNK_COOLDOWN_T`).
- 연속된 청크 4개에는 1차 계열이 2종 이상 있어야 한다.
- 가중치는 티어 범위의 중심에 가까울수록 높다(현재 방식 유지).
- 감독 규칙(5.8절): 쉼 청크, 적응 청크, 볼거리 청크.

### 7.5 결정론과 RNG 스트림
- `levelRng`: 메인 청크 i의 선택은 `sfc32(hash(seed, i))`로 한다. 티어와 풍경은 **메인 청크 누적 m**로 정하고 삽입 청크는 제외한다. 그래서 누가 어떻게 달리든 메인 코스는 같다.
- `bonusRng`(`seed ^ bonusIndex`): 하늘 청크, 파워업 종류.
- `skillRng`: 캐릭터와 짝꿍 효과.
- `fxRng`: 렌더 전용.
- 삽입 청크(`landing`, 하늘)는 메인 순번을 쓰지 않는다. `restartStreamAt`에서는 버린 메인 청크를 **같은 순번부터 다시** 놓는다.
- `src/sim`과 `src/data`에서는 `+ − × ÷`, `Math.sqrt/floor/round/min/max/abs`만 허용한다. `Math.sin/cos/tan/pow/exp/log/atan2/hypot`, `**`, `Math.random`, `Date`, `performance`는 금지한다(테스트로 강제).

### 7.6 스테이지 코스 고정
- `StageDef`를 확장한다: `{ id, world, index, name, biome, seed, tiers, length, course?: (chunkId | {pool: tag, tier})[], stars: { jellyPct } }`.
- `course`가 있으면 그 순서를 쓴다. `pool` 슬롯은 빌드할 때 스테이지 시드로 한 번 뽑아 **고정**한다. 그래서 스테이지는 매번 똑같고 유령도 항상 맞는다.
- 스테이지마다 볼거리 청크 1개와 복주머니 `B` 3개를 둔다.
- 복주머니 배치 원칙: 1번은 높은 길(발판이나 2단 점프 정점), 2번은 위험한 줄(위험물 사이의 슬라이드 줄), 3번은 계획형(일찍 보이지만 경로 선택이 필요).

### 8.4 오늘의 골목 (`daily`, 6판 후)
- 시드는 `fnv1a(현지 YYYY-MM-DD + '|' + CONTENT_HASH)`다. 같은 빌드라면 어느 기기에서든 같은 코스가 나온다.
- 규칙은 무한 달리기와 같지만 **혼자 달린다**(이어달리기 없음). 오늘의 주자 `CHARACTERS[dayIndex % 6]`와 오늘의 짝꿍 `COMPANIONS[dayIndex % 3]`을 **잠겨 있어도 빌려준다**.
- 도전은 무제한이고 최고 기록만 남긴다.
- 메달은 거리 기준으로 미리 공개한다. 초기값은 동 1,000 m, 은 2,000 m, 금 3,500 m이고 매일 코스 샘플 30개로 봇을 돌려 재보정한다.
- 최근 7일은 계속 도전할 수 있다. 연속 출석 대신 **「참여한 날 N일」**만 늘어난다.
- 선택형 기록 코드 `YYMMDD-점수-거리-체크섬`을 Web Share로 공유하고, 안 되면 클립보드에 복사한다.

### 8.5 시험 달리기
- 도감에서 60초 체험한다. 기록과 보상은 없다.

## 9. 메타 진행

### 9.1 재화
- **엽전** 하나뿐이다. 프리미엄 재화는 없다.
- **별**과 **계급 XP**는 모으는 수치일 뿐 쓰는 재화가 아니다.

### 9.2 명시적 금지
에너지·하트·판 수 제한, 뽑기·확률 상자, 스탯 강화·레벨업, 소모형 부스트, 유료·광고 부활, 광고, 결제, 계정, 서버, 타이머, 초기화되는 연속 출석, 기간 한정 보상, 친구 초대. 이 중 하나라도 필요해 보이는 기능 제안은 자동으로 기각한다.

### 9.3 미션 3칸 (`src/meta/missions.ts`)
- 서로 독립인 3칸이다. 템플릿은 **40개**(현재 15개 + 신규 25개)이고 각각 난이도 3단계다.
- 보상: 난이도별로 XP 1/2/3에 엽전 40/90/160.
- 배정 규칙
  - 보통 한 판에 끝낼 수 있는 미션이 1개 이상 있어야 한다.
  - 같은 동사 3개는 금지.
  - 별난 미션(`quirky`)은 최대 1개.
  - 특정 캐릭터 요구 금지. "N번 맞기", "N판 하기" 같은 숙제성 미션 금지.
  - 아직 열리지 않은 기능은 요구하지 않는다(`requires`).
- **바꾸기**는 언제나 무료다. 바꾼 미션은 보상이 없다.
- 봇으로 "10판 안에 완료 가능"을 검증한다. 달리는 중에 완료하면 1.5초 토스트를 띄우고 게임은 멈추지 않는다.

### 9.4 계급
- 0–30. 다음 계급까지 필요한 XP는 `min(3 + floor(r/3), 9)`이고, 30까지 총 207 XP다(약 6시간).
- 계급 보상은 엽전 `100 + 50r`에 더해 계급 5 꼬치, 계급 12 어묵이다. 그 밖의 계급은 칭호다.
- 다음 계급 보상을 **미리 보여 준다.**

### 9.5 업적 30개 (P1은 15개부터) → 각 업적이 꾸미기 1개를 연다
- 분류: 거리 6 / 수집 6 / 기술 6(아슬아슬, 흐름, 무피격) / 숙련 6(★3, 메달, 월드 클리어) / 호기심 6(숨김 5개, 힌트 한 줄).
- 보상 구성: 모자 12(갓, 복건, 머리띠, 족두리 등), 발자취 8(별가루, 불꽃, 김, 등불 등), 점프 소리 4, 캐릭터별 대체 팔레트 6(「○○로 2,000 m」).
- 판정은 판이 끝날 때만 `RunStats`와 누적 통계로 한다.

### 9.6 엽전 상점 (가격 고정, 영구)
- 달콩 2,500, 해돌이 3,500, 캐릭터별 두 번째 대체 팔레트 6개 × 800.
- 각 항목에 예상 판 수를 표시한다.
- 목표 수입은 중앙 실력 기준 판당 평균 120–180 엽전이다(주운 엽전 + 미션·계급 보상 분배).

### 9.7 해금 속도 목표 (봇 시뮬로 검증)
- 첫 해금 15–25분.
- 처음 3시간 동안 15–25분마다 하나씩 해금.
- 전부 해금 3–5시간, 별 63개 6–8시간.

### 9.9 저장 (`src/platform/storage.ts`, `src/meta/progress.ts`)
- 키 구성
  - `jelly_runner_v1`: 메인.
  - `jelly_runner_v1_bak`: 백업 사본.
  - `jelly_runner_ghost_<id>`: 유령. 하나에 하나씩, 전체 250 KB 이하. 현재 `Progress.ghosts`에서 분리한다.
- 쓰기 절차: 쓰기 → 다시 읽어 검증 → 이전 값을 `_bak`로 보관(현재 방식).
- **버전이 다르면 초기화하던 분기를 없애고 `migrations[v](o) → v+1` 체인으로 바꾼다.**
- 저장 시점: 판 종료, 해금, 설정 변경, `pagehide`.
- 첫 판이 끝난 뒤 조용히 `navigator.storage.persist()`를 호출한다.
- `QuotaExceededError`가 나면 최고 기록이 아닌 오래된 유령부터 지운다. 저장소가 막혀 있으면 메모리로 대신한다(현재 방식).
- 스키마 추가 필드: `companions`, `companion`, `pouches: Record<stageId, bitmask>`, `achievements`, `cosmetics{owned, equipped}`, `daysPlayed`, `scoreVersion`, 설정(`slideToggle`, `showPads`, `sideways`, `uiScale`, `shake`, `fps30`, `oneHand`).
- **백업 코드**: 설정에서 base64로 내보내고 가져온다(복사 버튼 + `.txt` 내려받기).

## 10. 화면 흐름과 UI

### 10.1 흐름
```
[부팅 ≤1초] ─▶ 타이틀 겸 첫 달리기 ──완주/건너뛰기──▶ 1-1 ──▶ [결과]
                                                          │
  ┌────── 다시 달리기 (사망→조작 ≤2.5초) ◀─────────────────┤
  ▼                                                       ▼
[달리기] ◀── 달리기(마지막 구성, 1탭) ── [홈] ◀───── 홈 ──┘
                                          ├─ 골목 지도 → 스테이지 카드 → 달리기
                                          ├─ 무한 달리기 → (준비 시트) → 달리기
                                          ├─ 오늘의 골목 → 달리기
                                          └─ 아이콘: 도감 · 미션 · 명예의 전당 · 설정
```
- **홈**
  - 큰 버튼 하나: **「이어서 달리기」**(다음 미클리어 스테이지, 모두 클리어했으면 무한 달리기).
  - 해금되는 대로 보조 버튼 2개: 무한 달리기, 오늘의 골목.
  - 오른쪽 위: 엽전, 별, 계급 막대. 아래: 아이콘 4개.
  - 주요 버튼은 최대 3개이고, 앱을 연 뒤 달리기까지 2탭 이하다.
- **준비 시트**: 주자, 파트너, 짝꿍을 칸으로 고른다. 마지막 구성을 기억한다. 홈에서 달리기를 누르면 이 시트를 건너뛰고, 작은 '바꾸기' 칩으로만 연다.
- **스테이지 카드**: 별 3조건, 복주머니 칸 3개, 최고 기록, 유령 켜기/끄기, 연습 시작점.

### 10.2 달리기 HUD (DOM, `src/ui`)
- **가로 화면**
  - 왼쪽 위: ⏸(44 px), 따끈함 막대(서리 아이콘, 위기 때 맥박), 그 아래 파워업 원형 타이머.
  - 막대 오른쪽: 잔치 글자 등불 5개(먹은 글자에 불이 들어옴).
  - 위 가운데: 점수와 흐름 불꽃, 진행 막대(스테이지 % 또는 최고 기록 대비).
  - 스테이지 전용 칩: 「별사탕 72% / 80%」, 복주머니 아이콘 3개.
  - **오른쪽 25%는 비워 둔다.**
  - 스킬 쿨다운 고리는 캔버스에 주자 머리 위로 그린다.
- **세로 화면**: 3.3절의 HUD 띠(3줄)를 쓴다.

### 10.3 일시정지 시트
- 버튼: **계속**, 처음부터, 그만하기, 설정.
- 손실을 강조하는 문구를 쓰지 않는다: 「여기까지 할까요? 기록은 저장돼요」.
- '계속'을 누르면 3-2-1 카운트다운(1.5초) 뒤 재개한다.

### 10.4 결과 화면 — 한 화면, 스크롤 없음, 0.35초 뒤부터 입력을 받고 새로 누른 `pointerdown`만 인정
1. **쓰러짐 카드**: 부딪힌 위험물의 실루엣과, 그것을 넘는 동작.

   | 원인 | 문구 |
   |---|---|
   | 가시 | 「석쇠 꼬챙이 — 한 번 점프」 |
   | 높은 탑 | 「찜통 탑 — 2단 점프」 |
   | 걸림 | 「청사초롱 — 슬라이드를 누르고 있기」 |
   | 낮은 천장 | 「낮은 처마 — 점프하지 말고 달리기」 |
   | 구덩이 | 「하수구 틈 — 끝에서 점프」 |
   | 다 식음 | 「다 식었어요 — 꿀물 길을 따라가요」 |

   (위험물 이름은 풍경 스킨을 따른다.)
2. **따끈함 장부 막대**: 시간 −88 · 부딪힘 3회 −45 · 구덩이 1회 −20 · 꿀물 +60.
3. **점수 내역**: 거리, 별사탕, 왕별사탕, 흐름 보너스, 한 줄, 아슬아슬, 보름달 잔치, 부수기, 엽전, 글자, 복주머니.
4. **'아깝다' 칩** (최대 3개, 가까운 순): 최고까지 84 m, ★2까지 2%, 글자 2개 부족, 80% 넘은 미션.
5. **타임라인** (P1): 피격마다 표시가 있고, 누르면 그 3초를 입력 기록으로 다시 시뮬해 0.5배속으로 보여 준다. 부딪힌 위험물에 외곽선을 친다.
6. **팁 한 줄**: 가장 많이 부딪힌 종류로 규칙에 따라 고른다.
7. 미션 체크와 해금 토스트는 화면 안에 표시한다. 모달을 연달아 띄우지 않는다.

- 버튼은 **다시 달리기**(가장 큼, 가로에서는 오른쪽 엄지 아래, 세로에서는 점프 패드 자리)와 **홈** 두 개뿐이다.
- 점프를 0.4초 누르고 있어도 다시 달린다. 숫자가 올라가는 애니메이션은 아무 곳이나 탭하면 건너뛴다.
- 스테이지를 클리어하면 별이 튀어나오고 '다음 스테이지' 버튼이 다시 달리기 옆에 붙는다. 이때만 버튼이 3개다.

### 10.5 설정
- **소리**: 배경음, 효과음 슬라이더(10단계), 음악 끄기.
- **조작**: 좌우 바꾸기, 버튼 표시, 슬라이드 토글, 눕혀서 하기, 한 손 모드(P2).
- **보기와 접근성**
  - 움직임 줄이기: 기본값은 `prefers-reduced-motion`을 따른다.
  - 화면 흔들림 0–100%.
  - 위험물 강조(외곽선을 굵게, 배경 채도를 낮춤), 효과 줄이기, UI 크기 100/115/130%, 배터리 절약(30 fps).
  - 진동: Android에서 `navigator.vibrate`가 있을 때만 표시.
- **도움**: 게임 속도 60–100%(10% 단위), 부딪혀도 따끈함 유지, 식는 속도 절반, 자동 슬라이드.
  - 자동 슬라이드는 `RunConfig` 플래그라서 리플레이가 결정적이다.
  - 도움을 켠 기록에도 별, 미션, 해금이 인정된다. 작은 '도움' 아이콘을 붙이고 명예의 전당에서 따로 모은다. '쉬운 모드'라는 말은 쓰지 않는다.
- **데이터**: 백업 코드 내보내기/가져오기. 안내 문구: 「사파리는 오래 열지 않으면 기록을 지울 수 있어요 — 홈 화면에 추가하거나 백업 코드를 저장해 두세요」.
- **카카오톡 인앱 브라우저**: UA에 `/KAKAOTALK/i`가 있으면 '기본 브라우저로 열기' 띠를 띄운다(P1).
- **개발 빌드 전용**: 판정 상자 오버레이.

### 10.6 명예의 전당
- 모드별·캐릭터별 로컬 상위 10개. 날짜, 도움 아이콘, 이어달리기 아이콘을 함께 보여 준다.
- 오늘의 골목은 날짜별 최고 기록과 메달.

### 10.7 문구 원칙
- 게임 안 문구는 모두 해요체다. 버튼은 6자 이하 명사형이다: 다시 달리기, 계속, 그만하기, 바꾸기, 시험 달리기.

### 11.4 가독성 규칙
1. **모양 문법**
   - 땅에서 솟은 것 = 점프.
   - 몸보다 큰 것 = 2단 점프.
   - 위에서 매달린 것 = 슬라이드.
   - 땅이 끊긴 것 = 점프.
   - 둥글고 빛나는 것 = 먹는 것.
   - 위험물은 각지고, 먹는 것은 둥글고 부드럽다.
2. 모든 위험물에 **바깥 3 px #140c1c + 안쪽 1.5 px #fff6e0** 이중 외곽선을 친다. 어떤 배경에서도 대비 4.2:1 이상이 보장된다. 현재 야시장 가시는 1.48:1이므로 반드시 바꾼다. 배경에는 외곽선을 쓰지 않는다.
3. 위험물 몸통은 어두운 저채도 색에 종류별 색조를 준다. 가시는 산호빛 빨강, 탑은 보라, 걸림은 파랑 계열. 색은 보조 단서이고 1차 단서는 모양이다.
4. 별사탕은 따뜻한 노랑과 분홍에 흰 반짝임이다. 엽전은 사각 구멍 난 금색 원, 꿀물은 호박색 잔이다.
5. **그리는 순서**: 시차 층 → 지면 → 이펙트(파티클 최대 180개, 풀링, 위험물 위에서는 알파 0.6 이하) → 먹는 것 → **위험물** → 주자 → HUD. 이펙트가 위험물을 절대 가리지 않는다.
6. 섬광 규칙: 화면 전체 섬광은 초당 3회 이하다. 피격 비네트는 150 ms, 알파 0.35 이하.

### 11.5 사운드 (WebAudio 절차 생성, `src/platform/audio.ts`)
- **배경음**: 풍경별 16마디 루프, 변주 2개. 구성은 장조 오음음계 리드, 베이스, 사인 킥, 노이즈 하이햇.
- **잔치 변주**: +15 BPM에 완전4도 위.
- **메뉴 루프**: 1개.
- **효과음** 약 24개
  - 조작: 점프, 공중 점프(휙), 슬라이드, 빠른 낙하, 착지.
  - 획득: 별사탕 음계 사다리, 왕별사탕 3화음, 엽전 두 음, 글자 종, 꿀물, 보름달 떡 팡파르, 한 줄 완성 화음, 복주머니.
  - 파워업: 왕만두, 질주, 자석 시작과 끝.
  - 위험: 위험물별 피격음 '쿵', 구덩이 구출, 아슬아슬.
  - 진행: 티어 상승 차오름, 위기 '덜덜', 교대, 되살아남.
  - UI: 버튼, 별 획득, 해금.
- **경고 전용 음색**: 두 번 짧게 치는 사각파. v2의 움직이는 위험물용으로 예약하고 다른 곳에 쓰지 않는다.
- `navigator.audioSession.type = 'ambient'`(지원될 때)로 사용자의 음악과 함께 섞이게 하고 무음 스위치를 존중한다.
- 결과 화면에서는 배경음을 50%로 낮춘다. `AudioContext`는 첫 `pointerdown` 때 `resume()`한다.
- 모든 소리 신호에는 **시각 신호 짝**이 있다. iOS 무음 스위치를 켜도 정보가 사라지지 않는다.

## 13. 테스트와 검증 계획

### 13.1 결정론 (`tests/determinism.test.ts`, 신규)
- **리플레이 해시**: 봇 판(무한, 스테이지, 데일리)의 `seed + log`를 다시 돌려서 600스텝마다 상태 해시가 같은지 확인한다. 대상 상태는 `body`, `hp`, `score`, `dist`, `rng`, `level.genX`.
- **금지 API 검사**: `src/sim/**`과 `src/data/**`의 소스를 읽어 정규식 `/Math\.(sin|cos|tan|pow|exp|log|atan2|hypot|cbrt|random)|\*\*|Date\.|performance\./`에 걸리면 실패다.
- **코스 동일성**: 같은 데일리 시드에서 서로 다른 입력으로 달려도 메인 청크 id 순서가 같아야 한다(7.5절).
- **교차 엔진**: e2e에서 Chromium과 WebKit(설치되어 있으면)에서 같은 리플레이의 최종 해시가 같은지 본다.

### 13.2 청크 검증 (`npm run validate`, `tests/chunks.test.ts` 확장, `tests/fairness.test.ts` 신규)
- 모든 청크, 모든 변형 조합, 티어 범위 안 20 px/s 간격마다 G1–G7을 검사한다. G8과 G9는 야간에 돈다.
- 실패 메시지에는 청크 id, 속도, 실패한 위상, 문제 열을 담는다.
- 테스트 자체의 회귀 확인: 이미 알려진 문제 패턴 '걸림 → 2열 → 가시'는 **G3에서 반드시 실패**해야 한다. 이 패턴은 창이 50–83 ms밖에 안 된다.
- 스테이지마다 복주머니 3개 모두가 기본 능력으로 무피격 경로에서 획득 가능해야 한다.

### 13.3 규칙 단위 테스트 (`tests/rules.test.ts` 확장)
- 모든 보상 쌍을 검사한다(왕만두, 질주, 자석, 잔치, 스킬, 이어달리기). 어떤 보상도 다른 보상의 시간을 줄이지 않아야 한다. 잔치 중 타이머 정지와 재획득 시 갱신(누적 아님)도 확인한다.
- 질주 종료 후 0.3초 안에 티어 속도로 돌아오고, 유예 중에는 피격이 0이어야 한다.
- 무적 규칙: 닿았던 위험물은 무해해지고, 무적은 겹쳐 있으면 연장된다. 히트스톱 동안 타이머가 정지한다.
- 구덩이는 −20과 구출이 일어나고 즉사는 없다. 해돌이 면제 2회를 확인한다.
- 되살아나기 → 이어달리기 → 쓰러짐 순서, 파트너가 자기 최대치의 50%로 시작하는지.
- 착지 예측: 착지 67 ms 전 입력은 지상 점프가 되고 공중 점프가 남아야 한다. 입력 큐: 한 프레임의 두 번 누름이 2단 점프가 되는지.
- 후반 가속과 600초 강제 종료. 점수 상한 999,999 불가침.

### 13.7 모바일 e2e (`npm run e2e`, `scripts/e2e.mjs`, Playwright)
- 뷰포트: **390×844(세로)**, **844×390(가로)**, **360×640**, 1280×720(데스크톱).
- 확인 항목
  1. 첫 탭이 점프이면서 `AudioContext`를 `running` 상태로 만든다.
  2. 더블탭 후 누르고 있기를 해도 텍스트 선택, `contextmenu`, 확대가 일어나지 않는다.
  3. 멀티터치: 슬라이드를 누른 채 점프하면 점프가 된다.
  4. 회전이나 `visibilitychange`에서 자동 일시정지하고, '계속'과 카운트다운 뒤에만 재개한다.
  5. 결과 화면 입력 보호: 쓰러지는 순간 연타해도 결과를 건너뛰지 않는다.
  6. 다시 달리기에서 조작 가능까지 2.5초 이하.
  7. 세로에서 패드 크기가 폭 180 px 이상, 높이 120 px 이상이고 캔버스가 16:9다.
  8. 로드 이후 **네트워크 요청 0건**.
  9. `localStorage`를 막아도 동작한다.
  10. CPU 4배 스로틀에서 프레임당 JS와 그리기가 p95 8 ms 이하(DPR 상한 2).
  11. 단일 파일 빌드 `play/index.html`로 한 판 완주.
- 판정 오버레이를 켜고 찍은 스크린숏에서 위험물 상자가 그림 안쪽에 있는지 확인한다.
