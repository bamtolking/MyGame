## 2. 밸런스 스윕 — `npm run balance` (10직업 × 2시드 × 180분, 약 6분)

전체 표: [`balance-results.md`](balance-results.md). 이야기를 따라가는 AI가 "사람" 역할(AI 동료 6명과 함께, 오프라인 설정과 동일). 비교를 위해 **모든 직업을 레벨 1부터** 플레이합니다(실제 게임에서는 해금 후 전직).

| 지표 | 목표 | 결과(20회) |
|---|---|---|
| Lv10 도달 | 약 20분 | 20~30분 |
| Lv20 도달 | 약 80분 | 80~110분 |
| Lv30 도달 | 2.5~3시간 | 135~170분 |
| 이야기 19장 완료 | 3시간 안 | **20/20 완료** |
| 첫 지역 보스 | 10분 안팎 | 1.9~11.9분 |
| 3시간 동안 쓰러짐 | 적게 | 1~22회, 중앙값 8.5 (주원인: 성난 장승 돌진, 여우 무녀, 구미호) |
| 불가사리 토벌 성공 | 대부분 성공 | 399/400 |
| 3시간 누적 금화 | 강화 +10 한 벌 ≈ 30만 | 37만~57만 |

v0.3 튜닝 과정에서 시뮬레이션이 찾아낸 것:
- AI 동료를 10직업에서 무작위로 뽑자 치유 직업이 빠져 쓰러짐이 2~3배(궁사 6→23회, 창술사 33~36회) → 내 곁 동료 3명 중 2명은 무녀·악사·수문장 중 지원 직업. 창술사는 체력·피해 감소·흡혈 소폭 상향.
- 화공 한 시드가 180분 안에 구미호를 못 잡음(장비 운 + 단일 대상 피해 부족) → 먹물 덩어리가 겨눈 대상에게는 온전한 피해. 재실행 시 두 시드 모두 19장 완료.
- 도사·화공이 원거리 요괴에게 자주 쓰러짐 → 체력·피해 감소 소폭 상향. 악사는 오라가 자신에게 적용되지 않도록 고친 만큼 공격력 +1.

## 5. 그래픽·사운드 검증 (v0.2)

- **스프라이트 전수 확인**: `npm run dev` → `/dev/art.html`이 직업 3종 × 11프레임, NPC 4종, 요괴 18종의 모든 프레임·상태, 소품 11종 × 변형 3, 한옥, 이펙트 텍스처 37종, UI 아이콘을 한 장에 그립니다. 이것을 캡처해 눈으로 검토했습니다.
- **전투 장면 캡처**: 헤드리스 Chromium(SwiftShader WebGL)에서 숲에 요괴 26마리 + 지역 보스를 배치하고 검객·궁사·무녀로 싸우며 연속 캡처. 베기 초승달, 불꽃 튐, 넉백, 용해 소멸, 레벨업 빛기둥·마법진, 필살기 컷인, 콤보 카운터, 경고 장판, 충격파가 그려지는지 확인했습니다.
  - 이 검토에서 찾아 고친 것: 빛·발광이 겹쳐 화면 가운데가 하얗게 날아감(조명 세기·블룸 문턱·발광 투명도 재조정), 달빛 나무·신당이 과노출, 이름표가 겹침(위로 밀어내기), 요괴 떼에서 피해 숫자 과밀(일반 숫자 상한), 동료의 레벨업 글자가 화면을 덮음(내 레벨업만 글자), 콤보 표시가 메뉴·레벨업 배너와 겹침.
- **Canvas2D 대체 경로**: 같은 장면을 저사양 설정으로 렌더해 조명·이펙트가 동작함을 확인(빛 번짐·왜곡 없음).
- **소리**: `tests/client.test.ts`가 모든 효과음·타악기·현악기 음을 Node에서 렌더해 NaN·클리핑·무음을 검사합니다. 브라우저에서는 워커 렌더와 곡 전환이 오류 없이 도는지만 확인했고, **사람 귀로 듣고 조율하지는 않았습니다.**
- **성능 주의**: 헤드리스 소프트웨어 WebGL은 5~20fps로 실제 GPU와 비교할 수 없습니다. 한 프레임의 CPU 쪽 작업(정렬·정점 작성·오버레이 글자)은 중앙값 1.6ms, 95% 6.1ms로 측정됐고 나머지는 소프트웨어 GPU 시간입니다.

## 6. 이 과정에서 테스트가 잡아낸 버그 (수정 완료)

- 마을 부활 지점 위에 한옥이 놓여 있음 → 한옥 이동.
- 신당 주변을 비우는 처리가 지역 경계 벽을 뚫음 → 같은 지역 타일만 비우도록.
- 접속 후 1초 동안 채팅이 "너무 빠릅니다"로 거절됨 → 쿨다운 초기값 수정.
- 마을 안에 서 있기만 해도 성벽 밖 처치 경험치를 받음 → 마을 안은 공유 보상 제외.
- 열린 시트가 사냥 중 초당 수 회 다시 그려져 닫기 버튼이 흔들리고 입력 중인 글자가 지워짐 → 시트별 관련 값만, 400ms 간격, 입력 중엔 갱신 안 함.
- HUD가 390px 폭에서 겹침, 클래스 카드에 CSS 클래스 충돌 → 레이아웃 재구성.

v0.2(그래픽·사운드 개편)에서:
- 효과음 `slash2` 끝부분에서 NaN(음수의 거듭제곱) → 포락선 계산에 경계 처리.
- 효과음 전체 렌더에 3초 이상 걸려 첫 소리가 늦음 → 톱니파를 polyBLEP로, 배음을 위상 누적으로 바꿔 약 1초, 그리고 Web Worker로 옮겨 화면이 멈추지 않게.
- 연타 콤보 표시가 피해 이벤트마다 DOM 재배치를 일으킴 → HUD 주기(100ms)에 한 번만 갱신.
- e2e에서 새로고침 후 저장이 사라진 것처럼 보임 → 조사 결과 **게임 코드가 아니라 테스트 도구 문제**: 문서 생성 시점에 localStorage에 쓰는 Playwright init script와 헤드리스 Chromium의 새로고침이 경쟁해 저장소 전체가 비는 현상(init script 사용 시 20회 중 5회, 미사용 시 11회 중 0회). 설정을 플레이어처럼 저장 → 새로고침 방식으로 바꿈.
- 소프트웨어 WebGL에서 한 프레임이 0.4초까지 걸리면 Chromium이 탭을 길게 누르기로 처리해 버튼이 반응하지 않음 → e2e에서 반응이 없으면 다시 탭(계속 무반응이면 실패로 기록).

## 7. 미검증

- 실제 iOS Safari / Android Chrome의 터치감, **WebGL 렌더 FPS(블룸·후처리 포함)**, 발열·배터리, GPU 메모리, 오디오(사람이 듣고 판단).
- 사람이 직접 3시간 플레이했을 때의 재미·난이도·완주 시간, 직업별 체감 밸런스.
- 실제 휴대폰에서 세로 잠금 상태로 가로로 들고 할 때의 편의(화면 키보드 위치, 주소창, 안드로이드 전체 화면·가로 고정).
- 인터넷 환경(지연 100ms+, 패킷 손실)에서의 예측·보간 체감. (로컬 네트워크에서만 확인)
