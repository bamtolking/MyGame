## 2. 밸런스 스윕 — `npm run balance` (3직업 × 2시드 × 180분, 약 2분)

전체 표: [`balance-results.md`](balance-results.md). 이야기를 따라가는 AI가 "사람" 역할(AI 동료 6명과 함께, 오프라인 설정과 동일).

| 지표 | 목표 | 결과(6회) |
|---|---|---|
| Lv10 도달 | 약 20분 | 20~35분 |
| Lv20 도달 | 약 80분 | 80~95분 |
| Lv30 도달 | 2.5~3시간 | 135~155분 |
| 이야기 19장 완료 | 3시간 안 | 6/6 완료 |
| 첫 지역 보스 | 10분 안팎 | 2.3~7.3분 |
| 3시간 동안 쓰러짐 | 적게 | 6~15회 (주원인: 성난 장승 돌진, 불가사리, 여우 무녀) |
| 불가사리 토벌 성공 | 대부분 성공 | 119/120 |
| 3시간 누적 금화 | 강화 +10 한 벌 ≈ 30만 | 49만~59만 |

튜닝 과정에서 고친 것(시뮬레이션이 찾아낸 문제):
- 경험치 곡선이 너무 완만해 Lv30이 1시간 만에 도달 → 곡선 조정(초반은 빠르게, Lv18 이후 가파르게).
- 반복 현상금이 60마리마다 끝나 금화·경험치의 대부분을 차지 → 250마리, 보상은 현재 레벨 필요 경험치의 10%.
- **도깨비 숲(Lv1~8) 바로 옆이 구미호 골짜기(Lv20~)라 초보 옆에 고레벨 요괴가 스폰되어 전멸** → 지역 경계에 벽을 세우고 길로만 통과, 스폰은 플레이어가 서 있는 지역만.
- 검객이 구미호의 부채꼴 탄막에 여러 발 동시에 맞아 한 번에 사망(3시간 27회) → 한 발동당 1회만 피격(→ 0~2회).
- 보스 근접 접촉 피해 과다, AI 동료 수만큼 보스 체력이 너무 빨리 증가 → 접촉 피해 ×0.6·간격 ×1.5, 인원당 +50%.
- 월드 보스 내려찍기를 사람 반응 속도로는 피할 수 없음 → 예고 1.1초→1.5초, 반경 230→210.

## 4. 브라우저 실기동 — `npm run e2e` : 53/53 통과

헤드리스 Chromium(소프트웨어 WebGL = SwiftShader, 터치 에뮬레이션, 기기 배율 2). 로그: [`e2e-report.txt`](e2e-report.txt)

- 휴대폰 390×844(**WebGL 고화질**), 작은 폰 360×640(**Canvas2D 저사양**), 가로 844×390(**WebGL 보통**) 각각: 타이틀 → 캐릭터 생성(궁사) → 마을(AI 동료 6명) → 렌더러 종류·그리기 호출 확인 → **실제 터치 드래그로 이동** → 30초 사냥(레벨업·처치·퀘스트 진행) → 전투 이펙트 확인(입자 수·콤보·충격파) → 가방·부적·퀘스트·지도·메뉴 시트 열기/닫기 → 채팅 왕복 → AUTO 자동 사냥 동작·조이스틱으로 해제 → 새로고침 → 이어하기로 같은 레벨 복원. **콘솔/페이지 오류 0.**
  - 휴대폰 WebGL 고화질: 스프라이트 286개를 그리기 호출 30번에, 30초 사냥 Lv2·처치 38·화면 속 요괴 143마리, 입자 최대 234개·콤보 72·충격파 동시 2개, 14fps
  - 작은 폰 Canvas2D 저사양: 스프라이트 157개를 그리기 호출 170번에, 30초 사냥 Lv3·처치 54·화면 속 요괴 69마리, 입자 최대 58개·콤보 90·충격파 동시 0개, 26fps
  - 가로 WebGL 보통: 스프라이트 181개를 그리기 호출 25번에, 30초 사냥 Lv3·처치 101·화면 속 요괴 73마리, 입자 최대 284개·콤보 133·충격파 동시 2개, 17fps
- FPS는 소프트웨어 렌더링 기준이라(5~26fps) 실제 기기 성능을 뜻하지 않습니다. v0.1(Canvas2D만)의 46~52fps와 비교할 수 없습니다.
- 온라인: 빌드된 클라이언트를 실제 서버가 제공, 브라우저 2개가 각자 캐릭터를 만들어 접속 → 서로 보임(사람 2명), 채팅이 건너감, 한쪽 이동이 다른 쪽 화면에 7px 이내로 보임(보간 지연 포함), 오류 0.

## 5. 그래픽·사운드 검증 (v0.2)

- **스프라이트 전수 확인**: `npm run dev` → `/dev/art.html`이 직업 3종 × 11프레임, NPC 4종, 요괴 18종의 모든 프레임·상태, 소품 11종 × 변형 3, 한옥, 이펙트 텍스처 37종, UI 아이콘을 한 장에 그립니다. 이것을 캡처해 눈으로 검토했습니다.
- **전투 장면 캡처**: 헤드리스 Chromium(SwiftShader WebGL)에서 숲에 요괴 26마리 + 지역 보스를 배치하고 검객·궁사·무녀로 싸우며 연속 캡처. 베기 초승달, 불꽃 튐, 넉백, 용해 소멸, 레벨업 빛기둥·마법진, 필살기 컷인, 콤보 카운터, 경고 장판, 충격파가 그려지는지 확인했습니다.
  - 이 검토에서 찾아 고친 것: 빛·발광이 겹쳐 화면 가운데가 하얗게 날아감(조명 세기·블룸 문턱·발광 투명도 재조정), 달빛 나무·신당이 과노출, 이름표가 겹침(위로 밀어내기), 요괴 떼에서 피해 숫자 과밀(일반 숫자 상한), 동료의 레벨업 글자가 화면을 덮음(내 레벨업만 글자), 콤보 표시가 메뉴·레벨업 배너와 겹침.
- **Canvas2D 대체 경로**: 같은 장면을 저사양 설정으로 렌더해 조명·이펙트가 동작함을 확인(빛 번짐·왜곡 없음).
- **소리**: `tests/client.test.ts`가 모든 효과음·타악기·현악기 음을 Node에서 렌더해 NaN·클리핑·무음을 검사합니다. 브라우저에서는 워커 렌더와 곡 전환이 오류 없이 도는지만 확인했고, **사람 귀로 듣고 조율하지는 않았습니다.**
- **성능 주의**: 헤드리스 소프트웨어 WebGL은 5~20fps로 실제 GPU와 비교할 수 없습니다. 한 프레임의 CPU 쪽 작업(정렬·정점 작성·오버레이 글자)은 중앙값 1.6ms, 95% 6.1ms로 측정됐고 나머지는 소프트웨어 GPU 시간입니다.

## 6. 이 과정에서 테스트가 잡아낸 버그 (수정 완료)

- 마을 부활 지점 위에 한옥이 놓여 있음 → 한옥 이동.
- 신당 주변을 비우는 처리가 지역 경계 벽을 뚫음 → 같은 지역 타일만 비우도록.
- 접속 후 1초 동안 채팅이 "너무 빠릅니다"로 거절됨 → 쿨다운 초기값 수정.
- 마을 안에 서 있기만 해도 성벽 밖 처치 경험치를 받음 → 마을 안은 공유 보상 제외.
- 열린 시트가 사냥 중 초당 수 회 다시 그려져 닫기 버튼이 흔들리고 입력 중인 글자가 지워짐 → 시트별 관련 값만, 400ms 간격, 입력 중엔 갱신 안 함.
- HUD가 390px 폭에서 겹침, 클래스 카드에 CSS 클래스 충돌 → 레이아웃 재구성.

v0.2(그래픽·사운드 개편)에서:
- 효과음 `slash2` 끝부분에서 NaN(음수의 거듭제곱) → 포락선 계산에 경계 처리.
- 효과음 전체 렌더에 3초 이상 걸려 첫 소리가 늦음 → 톱니파를 polyBLEP로, 배음을 위상 누적으로 바꿔 약 1초, 그리고 Web Worker로 옮겨 화면이 멈추지 않게.
- 연타 콤보 표시가 피해 이벤트마다 DOM 재배치를 일으킴 → HUD 주기(100ms)에 한 번만 갱신.
- e2e에서 새로고침 후 저장이 사라진 것처럼 보임 → 조사 결과 **게임 코드가 아니라 테스트 도구 문제**: 문서 생성 시점에 localStorage에 쓰는 Playwright init script와 헤드리스 Chromium의 새로고침이 경쟁해 저장소 전체가 비는 현상(init script 사용 시 20회 중 5회, 미사용 시 11회 중 0회). 설정을 플레이어처럼 저장 → 새로고침 방식으로 바꿈.
- 소프트웨어 WebGL에서 한 프레임이 0.4초까지 걸리면 Chromium이 탭을 길게 누르기로 처리해 버튼이 반응하지 않음 → e2e에서 반응이 없으면 다시 탭(계속 무반응이면 실패로 기록).
