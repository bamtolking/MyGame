# BALANCE_REPORT — 괴물 포장마차: 합치고 팔자!

첫 웹 베타의 밸런스 확인 결과. 숫자는 **봇 자동 플레이**(`npm run balance`, `tests/balance.test.ts`)와 **로직 실험**(`tests/experiments.test.ts`)에서 나온 실제 집계이며, 사람의 플레이 결과가 아니다. 사람 플레이는 아직 하지 않았다(아래 "검증하지 못한 내용").

봇: 급한 주문부터 필요한 음식을 아래 단계부터 만들어 준비되면 접수하고, 주문이 없을 땐 계열별 1단계 2개를 재고로 둔다. 프로필은 조작 간격과 새 주문을 읽는 지연으로 사람 속도를 흉내낸다: 초보 1.3초/조작·3초 지연, 보통 0.9초·2초, 빠름 0.6초·1초. 전체 표는 `docs/balance-results.md`.

## 2. 주문 부담과 서빙 가능성

- 주문 원료량(n단계 = 2^(n−1))의 상한은 1일차 4, 2·3일차 6, 4일차 12, 5일차 10. 4일차의 4단계+3단계(12) 주문은 생성 12회 + 합성 11회 + 접수 1회 = 24회 조작이 필요하다. 마녀의 인내 (36 + 5×11) × 1.2 = 109초로 설정했다. 봇은 접수까지 25~35초.
- 원료량 합(도착한 손님 기준)은 시드에 따라 1일차 12~20, 2일차 18~41, 4일차 30~50, 5일차 23~44였다(`docs/balance-results.md` 표의 "원료량").
- 봇 기준 주문 대기 이탈은 거의 0이다. 즉 인내 시간은 조작 속도가 일정한 봇에게는 여유롭다. 사람은 읽기·실수·동시 주문으로 느려지므로 실제 이탈은 더 나올 것이다. 사람 플레이 후 `customers.ts`의 `basePatience`/`patiencePerRaw`로 조정할 것.

## 3. 수입과 구매 가격

- 기본 가게로 1일차 3별(수입 134)을 하면 세 번째 좌석(60) + 장식(40)을 살 수 있다. 2일차 한 번(≈215)이면 직원 속도 1단계(80)나 네 번째 좌석(120)이 가능하다.
- 총 강화 비용 60+120+40+40+80+160 = 500코인. 2~3일차를 두 번씩 돌면 모두 살 수 있는 수준이다.
- 강화 가게(좌석 4·장식 2·속도 2·배식구 인접 배치)의 봇 결과: 2일차 11.9~12.0/12, 5일차 11.9~12.0/12 서빙, 수입 2일차 276, 5일차 356~366. 도전 수입 목표(240, 360)는 강화 가게 + 보통 이상 조작이면 달성된다.

## 6. 점검 항목별 판단

- 낮은 단계 음식도 남겨둘 이유가 있는가? — 있다. "무조건 합치기" 봇은 2일차 서빙 9~12, 주문 이탈 2명, 보드 꽉 참 700~1100회로 "남기기" 봇(12명, 이탈 0)보다 나빴다(`docs/balance-results.md` "무조건 합치기 vs 낮은 단계 남기기").
- 모든 음식을 최고 단계로 만드는 것이 항상 정답인가? — 아니다. 1~2일차 주문의 55~60%가 1단계이고, 높은 단계는 낮은 단계 주문에 쓸 수 없다.
- 좌석을 늘렸을 때 새로운 부담이 생기는가? — 부분적으로. 동시 주문이 늘어 조작 부담은 커지지만, 봇 기준으로는 순이익만 있었다. 사람 플레이에서 확인 필요.
- 가구 배치가 실제 동선에 영향을 주는가? — 그렇다(실험 A, 배치 비교).
- 주문을 읽는 시간보다 터치 반복이 지나치게 많은가? — 4단계 하나에 31회 조작이 필요하다. 길게 누르기로 생성은 줄였지만 합성 15회는 남는다. 사람 플레이에서 피로도를 봐야 한다.
- 첫 영업일이 초보자에게 과도하게 어려운가? — 봇 기준 아니다(초보 프로필 8/8). 사람 기준 미확인.
- 후반은 판단이 어려워지는가, 손만 바빠지는가? — 5일차는 12명 + 1~4단계 혼합이라 우선순위 판단이 필요하지만, 4단계 합성의 터치 횟수도 많다. 실제 플레이 후 4단계 비중(`tierWeights`)을 낮출 수 있다.
