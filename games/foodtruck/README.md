# 괴물 포장마차: 합치고 팔자! (웹 베타)

합성 퍼즐 + 주문 처리 + 소규모 가게 운영. 작은 괴물들이 밤마다 찾아오는 포장마차를 운영합니다.
서버·로그인·결제·광고 없음. 휴대폰 브라우저에서 바로 플레이하는 HTML5 게임입니다. (Android·iOS 앱은 아직 없습니다.)

> 한 문장: **손님 주문을 보고 무엇을 합칠지 고민하고, 가게를 바꾸면 실제 운영이 달라지는 3분짜리 영업.**

## 1. 필요한 환경

- Node.js 22 (LTS). `node --version`으로 확인.
- 휴대폰 테스트: PC와 같은 Wi‑Fi에 연결된 Android/iOS 휴대폰의 Chrome/Safari.

## 2. 설치·실행·테스트·빌드

이 게임은 저장소의 `monster-stall/` 폴더에 있는 독립 프로젝트입니다. (같은 저장소의 `대박수비대`는 별개의 게임이며 서로 영향을 주지 않습니다.)

```bash
cd monster-stall
npm install            # 의존성 설치 (최초 1회)
npm run dev            # 개발 서버. 터미널에 표시되는 주소를 브라우저로 열기
npm run typecheck      # 타입 검사
npm run test           # 규칙·경제·저장·경영 효과 로직 테스트 (약 1초)
npm run balance        # 봇 밸런스 스윕 → docs/balance-results.md 갱신
npm run build          # 타입검사 + 빌드 → dist/ 와 play/index.html (파일 하나짜리)
npm run e2e            # 헤드리스 Chromium으로 휴대폰 뷰포트 3종 실기동 + 스크린샷 (e2e-out/)
```

### PC에서 열기

- 개발 서버: `npm run dev` 후 `http://localhost:5174/` (포트가 사용 중이면 Vite가 다른 포트를 골라 터미널에 표시합니다).
- 서버 없이: `npm run build`로 만든 `play/index.html` 파일 하나를 브라우저로 열면 됩니다.

### 휴대폰에서 열기

1. PC에서 `npm run dev`를 실행하면 터미널에 `Network: http://<PC의 IP>:5174/` 주소가 나옵니다.
2. 휴대폰을 **PC와 같은 Wi‑Fi**에 연결하고 그 주소를 휴대폰 브라우저에 입력합니다. (`localhost`는 휴대폰에서 열리지 않습니다.)
3. 개발 서버를 끄면 접속이 끊깁니다. PC 방화벽이 5174 포트를 막으면 허용해야 합니다.
4. 서버를 쓰기 어려우면 `play/index.html` 파일을 메신저·메일로 휴대폰에 보내 브라우저로 열어도 됩니다.
5. 외부 공개(호스팅)는 별도 승인 후 진행하세요. 이 저장소는 공개 배포 설정을 포함하지 않습니다.

## 3. 게임 조작

- **하루의 흐름**: 영업일 선택 → 손님·목표 확인, 가구 배치·구매 → 영업 시작(180초) → 주문 처리 → 마감 정리 → 정산 → 가게 손보기 → 다음 영업일.
- **합성 보드(5×5)**: 음식 누르기 → 같은 음식 누르기 = 합성(두 번째 칸에 한 단계 위 음식). 음식 누르기 → 빈칸 누르기 = 이동. 드래그 없음.
- **생산 버튼**: 구이·음료·디저트 버튼이 각 계열 1단계 음식을 1개 만듭니다. 길게 누르면 연속 생성, 손을 떼거나 보드가 차면 멈춥니다. 재료비는 없고, 제약은 보드 공간과 시간입니다.
- **주문 카드**: 손님 얼굴, 필요한 음식과 수량, 남은 인내(막대+초). 필요한 음식이 모두 있으면 "준비 완료"가 켜지고, 카드를 누르면 음식이 보드에서 빠져 직원 서빙 대기열에 들어갑니다. 준비 전 카드를 누르면 필요한 음식이 보드에서 강조됩니다.
- **직원**: 배식구에서 음식을 받아 좌석 옆 칸까지 걸어가 전달하고 돌아옵니다. **전달된 순간에만** 판매액·팁이 들어옵니다.
- **정리**: 음식을 고른 뒤 "정리"로 그 음식 1개를 없앱니다(코인 없음). 2단계 이상은 확인창이 뜹니다.
- **시간**: 150초부터 새 손님이 오지 않고, 180초에 생산·합성·접수가 끝나며 접수된 서빙만 마무리합니다. 마감 중 "빠르게 보기"로 배속할 수 있습니다.
- **일시정지(⏸)**: 시간·손님·직원·연속 생성이 모두 멈춥니다. 도움말·설정을 열어도 멈춥니다. 화면을 벗어나면 자동 정지, 돌아오면 확인 후 재개.
- **마감하고 돌아가기**: 일시정지 메뉴에서 선택. 새 주문·생산이 끝나고 실제 판매한 수입만 정산됩니다.
- **가게 배치(영업 준비 중에만)**: 가구 누르기 → 빈칸 누르기 → 미리보기 → 확정. 배식구·출입구를 막거나 좌석에 갈 수 없는 배치는 거부됩니다. 점선은 직원의 실제 경로이며 칸 수·편도 시간이 표시됩니다.
- **구매·강화**: 세 번째 좌석 60, 네 번째 좌석 120, 장식 40(최대 2개), 직원 속도 80/160 코인. 장식은 상하좌우로 붙은 좌석의 주문 인내를 +5초(좌석당 최대 +10초) 늘립니다.

### 규칙 요약

- 영업 시작 시 계열별 1단계 음식 2개씩(총 6개)을 받습니다. 남은 음식은 다음 날로 이월되지 않고 코인으로 바뀌지도 않습니다.
- 주문은 메뉴 1~2개. 정확히 같은 계열·단계·수량이 있어야 접수됩니다. 높은 단계로 낮은 단계 주문을 대신할 수 없습니다.
- 좌석이 없으면 최대 3명이 줄을 섭니다(대기줄 인내). 앉으면 주문 인내가 줄고, 접수하면 멈춥니다.
- 팁 = 판매액 × 손님 팁 비율 × (접수 시 남은 인내 60% 이상: 1 / 30% 이상: 0.5 / 미만: 0).
- 별: ⭐ 목표 서빙 인원 / ⭐⭐ 영업일별 이탈·만족 기준 / ⭐⭐⭐ 도전 수입. 별은 영업일별 최고 기록으로 저장됩니다.
- 활성 단계: 1일차 1~2단계, 2~3일차 1~3단계, 4~5일차 1~4단계. 그날 만들 수 없는 단계는 주문되지 않고 합성도 막힙니다.

## 4. 저장과 이어하기

- 이 기기의 브라우저(localStorage)에만 저장합니다. 계정·서버 없음.
- 영업 중 3초마다, 그리고 합성·접수·전달·구매·정산·배치 변경 뒤에 전체 상태를 한 번에 저장합니다.
- 제목 화면의 "영업 이어하기"는 **가장 최근 저장 지점부터 일시정지 상태로** 시작합니다. 매 프레임 복원을 약속하지 않습니다.
- 앱을 닫아둔 시간은 영업에 적용되지 않고 오프라인 수입도 없습니다.
- 정산은 영업 실행 ID 기준 한 번만 반영됩니다. 결과 화면을 새로고침해도 코인이 늘지 않습니다.
- 저장이 실패하면 일시정지 메뉴·설정에 "저장 실패"로 표시됩니다.
- 저장 데이터가 손상되면 시작 시 안내창이 뜨고, "초기화하고 새로 시작"으로 복구할 수 있습니다(손상 데이터는 브라우저에 백업 키로 남김).

### 저장 초기화

제목 화면 → 설정 → "저장 초기화", 또는 제목 화면의 "처음부터 새로 시작". 브라우저 개발자 도구에서 `localStorage`의 `monster-stall.save.v1` 키를 지워도 됩니다.

## 5. 구조

```
src/data/      음식 12종·손님 6종·영업일 5개·가게 격자·밸런스 수치 (숫자는 여기만 수정)
src/sim/       순수 로직(DOM 없음): rng, board(합성), store(배치·BFS 경로·장식), orders(주문·일정),
               run(손님 상태·직원 이동·결제·마감), result(정산·별·조언), meta(코인·구매·해금), save(직렬화·검증)
src/render/    SVG 아이콘(음식·손님·가구), Canvas 2D 가게 렌더러(손님·직원 이동·대기줄·파티클)
src/ui/        화면(제목·영업일·배치·영업·결과), 대화상자·토스트, 도움말
src/platform/  localStorage 저장, WebAudio 절차적 효과음
tests/         Vitest 로직 테스트 + 경영 효과 실험 + 봇 밸런스 스윕
scripts/       단일 파일 빌드, Playwright 모바일 e2e
docs/          밸런스 스윕 결과(자동 생성)
```

자세한 내용: `DEVELOPMENT_NOTES.md`(구조·규칙·현재 상태), `TEST_REPORT.md`(수행한 테스트), `BALANCE_REPORT.md`(밸런스 확인 결과).

## 6. 미술·음향 출처

모든 그래픽은 코드로 생성한 SVG/Canvas이고, 효과음은 WebAudio로 합성합니다. 외부 자산·폰트·라이브러리 이미지는 사용하지 않습니다.
