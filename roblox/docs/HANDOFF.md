# 저승 휴게소 — 인수인계 (2026-09-21, v0.3.0-beta.1)

## 지금 상태
- 이 게임을 만들며 사용자와 나눈 대화 전문은 `docs/CHAT_HISTORY.md` 에 있다. 사용자가 무엇을 원했고 어떤 피드백을 줬는지는 그 파일이 원문이다.
- 플레이 가능한 베타. 사용자가 Roblox Studio 에서 실제로 플레이해 자가 진단 서버 17개·클라이언트 7개 항목 전부 통과, 스크립트 오류 0건을 확인함(손님이 물리로 걸어와 카운터에 서고, 서빙하면 성불하는 것까지).
- 헤드리스 통합 시뮬레이션(Lune) 90개 검증 통과, Roblox API 타입 검사 오류 0, 순수 로직 테스트 8종, 속성 이름 검사 1,000여 개 통과.
- 아직 게시(퍼블리시)하지 않음. 게시 전에는 DataStore 경고가 뜨지만 정상.

## 구현된 시스템 (요약)
- 핵심 루프: 준비 15초 → 밤(손님 웨이브) → 낮 25초(상점·준비 투표·유물 투표) → … → 평판 0 이면 폐업(결과·리뷰) → 자동 재시작.
- 요리 8종(어묵탕·라면·호떡·떡볶이·붕어빵·인절미·모둠 튀김·김밥), 조리대 9종(상자·도마·조리대·냄비·화덕·튀김기·밥솥·떡메·쓰레기통) + 소화기함.
- 손님 6종 + 보스 산신령(5의 배수 밤). 구미호는 인내심 절반에서 주문을 바꿈. 만족한 손님은 승천(성불).
- 콤보, 화재(탄 음식 → 발화 → 번짐 → 소화기), 밤 이벤트 5종, 밤 목표 6종, 부적 3종(팀 게이지), 유물 9종(보스 밤 뒤 투표), 상점 업그레이드 9종.
- 영구 진행: 명성·모자 9종(옷장), 최고 밤·서빙 저장, 전체 순위표(OrderedDataStore, 주방 벽).
- 연출: 요리 날아가기, 손님 둥실거림/점프/떨림, 카메라 흔들림, 번개, 폭죽, 정전, 비네트, 조리 거품·김·달아오른 화덕, 야시장 장식, 주방 소품.
- 온보딩: 첫 손님 튜토리얼 체크리스트, 주문 목록 HUD, 프롬프트 문구 맞춤, 손님 대사.
- 개발 도구: Studio 자가 진단(플레이 시 출력 창 요약), 실행(Run) 모드 무인 시연, run-in-roblox 스크립트, Lune 시뮬레이션, CI.

## 설계 결정과 이유
- 에셋 없이 파츠·파티클·내장 사운드만: 파일 하나로 열리고, 어떤 계정에서도 동작하며, AI 가 검증할 수 있음.
- 상태 복제는 Attribute: 늦게 들어온 플레이어 동기화가 공짜이고, 클라이언트가 서버 시각으로 진행 바를 스스로 그려 네트워크 부하가 거의 없음.
- 손님은 귀신이라 충돌 그룹으로 카운터를 통과하고, 애니메이션 대신 떠다님(클라이언트에서 Weld C0 로 둥실거림).
- 서버 권위: 클라이언트가 보내는 것은 프롬프트 입력과 구매·투표·부적 요청뿐.
- 협동을 규칙으로 강제하는 장치는 떡메치기(번갈아 치기) 하나뿐이고, 나머지는 동선·타는 음식·인내심으로 자연스럽게 분업이 생기게 함.

## 알려진 제한
- Studio 실기동은 사용자 1명 플레이만 확인함. 2명 이상 로컬 서버 테스트, 모바일, 게시 후 DataStore·순위표는 미확인.
- 배경음악 없음 (`Config.MusicId` 에 오디오 ID 를 넣으면 재생).
- 밸런스는 봇·시뮬레이션 기준. 사람 3~4명 플레이 데이터로 `Waves.customerCount`·`patienceMultiplier`·`Config.FireDelay` 조정 필요 (목표: 첫 판 4~6밤, 익숙해지면 10밤+).
- 시뮬레이션 초기에 밤 5 손님 도착이 늦어 실패한 적이 1회 있었으나 이후 8회 연속 재현되지 않음(흉내 환경의 타이밍 문제로 추정).
